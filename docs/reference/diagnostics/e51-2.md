# E5173 to E5272: what a host makes, JSX, C calling Jac, Rust and C++ instances, a class body's try, a surrogate pair, an extension's links and entries, a runtime as a program

These codes refuse what neojac cannot build as written for the host or the toolchain at hand: a
class Python would make as the program runs, in a program whose classes are known as it
compiles; JSX in a space with no JSX runtime; native code (C, Rust, C++) that cannot be linked
or compiled as the program needs it; a string literal a JavaScript host's UTF-16 text would
read as another string; and a module of a space's runtime named as the program. In a template, `{name}` is filled in when the error is reported.

## E5173

```text
an import in a code body loads a Python module as it runs, on a cpython host; '{name}' is {what}
```

In a cpython space, an import in a function or other code names `{name}`, which Python cannot
load where the import runs. `{what}` says why: `not a module's name` (a path, an `include` or a
`comptime import`), or `a Jac module, which its wire brings in`. A name Python has no module of
is W1100, `cannot find module`, as at a module's top level. An import in a code body is Python's
there, made as it runs. See
[Classes and decorators in a cpython space](../../interop/python-classes.md#an-import-in-a-code-body).

**Fix:** import a Python module by its name, and a module of the project through its wire, at
the module's top level or, for a Jac module, in the body under a wire that admits it.

## E5174

```text
'{name}' is decorated by '{deco}', which Python runs as the {kind} is made: Python makes it with its decorators applied in a cpython space, and a decorator of a {host} program is compile time
```

A class or a function `{name}` of a native or JavaScript program is decorated by `{deco}`, a
Python callable. Python runs such a decorator on the class or function as it is made, which a
cpython space does; a decorator of a program whose classes and functions are known as it
compiles is a compile-time function of the program
([Decorators](../../language/decorators.md)).

```jac
# expect: E5174 x2
import contextlib;
import from dataclasses { dataclass }

@dataclass
class EmailData {
    has subject: str;
}

@contextlib.contextmanager
def tagged(name: str) -> any {
    return name;
}

with entry {
    print(EmailData(subject="hi").subject);
}
```

**Fix:** put the module in a cpython space
([Classes and decorators in a cpython space](../../interop/python-classes.md)), or write what
the decorator gives in Jac: a `dataclass` is an `obj`, whose fields, constructor, equality and
repr Jac makes.

## E5175

```text
class '{name}' declares members under an `if` on {test}, which is known only as the program runs: Python makes such a class in a cpython space, running its body where its statement runs, and a {host} program's class is known as it compiles: test the target with `comptime if`
```

An `if` among the members of the class `{name}` tests `{test}`, which only the running program
knows. A cpython space makes such a class as its statement runs; a native or JavaScript
program's classes are known as it compiles.

```jac
# expect: E5175
glob HAS_THREADS: bool = True;

class Proc {
    if HAS_THREADS {
        def threads -> int {
            return 2;
        }
    }
}

with entry {
    print(Proc());
}
```

**Fix:** where the test is the platform, test the target as the program compiles:
`comptime if target().os != "windows"` ([comptime if](../../language/compile-time.md#among-declarations-and-members)).
Otherwise declare the members, and test as they run.

## E5176

```text
class '{name}' is declared in a code body, which Python runs where its statement runs, making a new class each time: Python makes such a class in a cpython space, and a {host} program declares its classes at module level
```

The class `{name}` is declared in a function, a method or a `with entry` block of a native or
JavaScript program (`{host}`). Python makes a class there each time its statement runs, which a
cpython space does
([Classes and decorators in a cpython space](../../interop/python-classes.md#a-class-in-a-code-body));
a program whose classes are known as it compiles declares them at its top level.

```jac
# expect: E5176
def shown -> any {
    obj Short {
        has n: int = 1;
    }
    return Short();
}

with entry {
    print(shown());
}
```

**Fix:** declare the class at the module's top level, or put the module in a cpython space.

## E5177

```text
class '{name}' is declared in a code body and reads '{local}', a name of the body it is in: neojac does not yet make a class that reads its body's names
```

In a node, browser or hermes space, the class `{name}`, declared in a code body, reads `{local}`,
a parameter or a local of that body. JavaScript makes such a class where its statement runs, and
neojac makes one there only when it reads none of the body's names. In a cpython space Python makes
the class, and its methods read the body's names as Python's closure does
([Python classes](../../interop/python-classes.md#a-class-in-a-code-body)).

<!-- example: not checked: runs in a node space -->
```jac
obj Base {
    def shown(x: int) -> str {
        return str(x);
    }
}

def made(n: int) -> any {
    obj Shown(Base) {
        def shown(x: int) -> str {
            return str(x + n);
        }
    }
    return Shown;
}
```

**Fix:** give the class what it reads as a field (`has offset: int = 0;`, read as `self.offset`),
pass it to its methods, or put the module in a cpython space.

## E5178

```text
JSX in a {host} space whose `ui` plugin '{plugin}' names no JSX runtime: its `[ui.jsx]` table's `source` is the package whose `jsx-runtime` makes the elements
```

A module of a node space holds JSX, and the space's `ui` plugin `{plugin}` names no package to
make its elements: the standard plugin `none` names none. A JSX element is a call of a JSX
runtime's `jsx`, which the plugin's `jac.toml` names
([Hosts](../../apps/hosts.md#node)).

```toml
# the ui plugin's jac.toml
[ui.jsx]
source = "react"
```

**Fix:** bind the space to a `ui` plugin whose `[ui.jsx]` names a `source` (React's
`react/jsx-runtime`), or move the component to a browser space.

## E5183

```text
the C module '{module}' is built into the shared library '{lib}', which cannot call the program's Jac function '{name}': a C module that calls Jac is linked into the program
```

A wire gives the Jac function `{name}` to the C module `{module}`, whose table says
`shared = "{lib}"`. A shared library is built before the program and loaded by it, so it cannot
link to a function of the program. See
[C modules](../../interop/c-modules.md#calling-jac-from-c).

**Fix:** take `shared` out of the C module's table, so that it is linked into the program, or
leave the Jac function out of its wires.

## E5190

```text
the Rust items the program imports cannot be read or built: {what}
```

A program imports items of Rust (of `std`, or of a crate a Jac file of a crate names) and rustc
cannot read them or build what binds them. `{what}` is rustc's or cargo's reason: a dependency
the crate inherits from a workspace that cannot be resolved, two crates of the program that
depend on one name differently (`two crates depend on 'serde' differently`), crates that do not
link together. See [Rust modules](../../interop/rust-modules.md).

**Fix:** as `{what}` says: give the crates one version of the dependency they share, or resolve
it in the workspace.

## E5200

```text
libcxx, the program's C++ standard library classes and the instances of class templates Jac classes derive, does not compile: {names}
```

neojac writes one C++ unit for a program, `libcxx`: the classes of the C++ standard library the
program uses (`std_string`, `std_vector[i32]`), and each C++ class template a Jac class derives,
made with that class (`obj Heavy(Counted[Heavy])`). That unit does not compile: Clang's errors
are printed first, and `{names}` are the instances and classes it was making. Most often a Jac
method's types disagree with the template's virtual method of that name, or with what the
template calls on `T`, or a type argument is one its template does not take. A `std_` name `std`
does not have is E1145 of the import, not this. See
[C modules](../../interop/c-modules.md#a-jac-class-deriving-a-c-class).

**Fix:** give the Jac methods the types the template's C++ gives them (`override def unit ->
i32` for C++'s `virtual int unit() const`), and name a standard library class as the library
spells it, with type arguments it takes.

## E5220

```text
class '{name}' declares members in a `try`, whose arms run as the program runs: Python makes such a class in a cpython space, running its body where its statement runs, and a {host} program's class is known as it compiles
```

A `try` among the members of the class `{name}` declares members as its arms run: the block's
until a statement raises, a handler's where one matches. A cpython space makes such a class as its
statement runs ([A class body's `try`](../../interop/python-classes.md#a-class-bodys-try)); a
native or JavaScript program's classes are known as it compiles. `{host}` is the space's host.

```jac
# expect: E5220
class Proc {
    try {
        static has limit: int = int("4");
    } except ValueError {
        static has limit_unknown: bool = True;
    }
}

with entry {
    print(Proc());
}
```

**Fix:** put the module in a cpython space, or declare the members once and compute their values
where the program runs: `static has limit: int = parsed_limit();`, with the `try` in that
function.

## E5221

```text
this str holds the surrogates {high} and {low} side by side, two code points, and a {host} space's strings are UTF-16 text, in which the two are the one character {char}
```

A str literal in a space of a JavaScript host (`node`, `browser`, `hermes`) holds a high surrogate
and a low surrogate side by side, written as two escapes (`"\ud83d\udc4d"`). In Jac, as in
Python, the two are two code points, a string of length 2. A JavaScript host's strings are UTF-16
text, in which a high and a low surrogate side by side are the one character `{char}` they encode,
of length 1: the program would see another string than it wrote, so the literal is refused when
the program compiles. A lone surrogate is held as it is, and a `bytes` literal holds bytes. See
[Where the language differs by host](../../apps/hosts.md#where-the-language-differs-by-host).

<!-- example: not checked: needs a node space -->
```jac
glob THUMB: str = "\ud83d\udc4d";

with entry {
    print(len(THUMB));
}
```

```text
main.jac:1:19: error[E5221]: this str holds the surrogates \ud83d and \udc4d side by side, two code points, and a node space's strings are UTF-16 text, in which the two are the one character U+1F44D
```

**Fix:** write the character the pair encodes, `"\U0001f44d"`, where the character is meant; it
is one code point on every host. Where the two code points are meant, the program cannot hold them
in a JavaScript host's `str`: keep them as numbers, or put the module in a native or cpython space.

## E5270

```text
the extension module '{extension}' leaves {names} to the process that loads it, though the project's C module '{module}' defines them: an extension's row links the C modules its `links` names, which `neojac absorb --record` writes from the link it records
```

An extension module built from a C module (its `[extensions."<path>"]` row names `c`) was linked,
and it still needs functions or data, `{names}` (the first three, and how many more), that a file
of another of the project's C modules, `{module}`, defines. The extension links its own C module
and the C modules its row's `links` names ([`[extensions."<path>"]`](../jac-toml.md#extensionspath)),
and no others: the archwire's flows say which names move between files, not what a build links.
A symbol an extension leaves undefined is resolved by the process that loads it, from whatever it
finds there, and the process's copy is not the project's: Node exports libuv's functions
(`uv_version` among them), so an addon that vendors a library of those names would run on Node's
copy of it, or fail to load where the process has none. The build
reports it after the link, on both ways an extension is built (from the C module's C and C++,
and from its Jac once `neojac port` has taken them), and removes the extension it made. Once
the row links the module, its definitions are the extension's own: an extension exports its entry
points alone and keeps every other definition local, so its calls reach the vendored copy on
every system ([`[extensions."<path>"]`](../jac-toml.md#extensionspath)).

A row recorded before `links` existed has none, and meets this the first time it is built.

```toml
[c.addon]
sources = ["twin.cpp"]
include = ["../vendor"]

[c.vendor]
sources = ["uvish.c"]
headers = ["uvish.h"]

[extensions."build/Release/twin"]
c = "addon"
```

```text
jac.toml:1:1: error[E5270]: the extension module 'build/Release/twin' leaves 'uv_version' to the process that loads it, though the project's C module 'vendor' defines them: an extension's row links the C modules its `links` names, which `neojac absorb --record` writes from the link it records
```

**Fix:** run `neojac absorb --record` again, which writes `links` from the link the project's own
build made, or add the module to the row: `links = ["vendor"]`.

## E5271

```text
the extension module '{extension}' does not define {names}, {what}: a library loaded by its own convention names the C names it gives in its row's `exports`, which `neojac absorb --record` writes from the build it records
```

An extension module exports its entry points and nothing else
([`[extensions."<path>"]`](../jac-toml.md#extensionspath)), and the files this one would link
define none of `{names}`, an entry it needs. `{what}` says which entry that is:
`the entry by which Python starts an extension module` (`PyInit_<name>`, for a row of a Python tree
or of no tree); `the entry by which Node starts an addon of an npm tree` (`napi_register_module_v1`; the
version entry beside it is optional, and the message names it as such); or
``which its row's `exports` names``, for a name the row lists that nothing it links defines. The
build reports it before the link, from the definitions of the files it would link, on both ways
an extension is built, and writes no extension. It points at the row in `jac.toml`: at its
`exports` where it has one, else at its `c` or `jac`.

A shared library a package loads another way (with `ctypes`, with `dlopen`, as a loadable
extension of another library) has none of its tree's entries: its row says what it gives, in
`exports`. A row recorded before `exports` existed has none, and meets this the first time it is
built.

```toml
[project]
name = "fast"

[extensions."fastlib/_plug"]
c = "csrc/plug"
```

```text
jac.toml:5:1: error[E5271]: the extension module 'fastlib/_plug' does not define 'PyInit__plug', the entry by which Python starts an extension module: a library loaded by its own convention names the C names it gives in its row's `exports`, which `neojac absorb --record` writes from the build it records
```

**Fix:** run `neojac absorb --record` again, which writes `exports` from the build it records, or
name what the library gives in its row: `exports = ["plug_init"]`.

## E5272

```text
'{module}' is a module of the runtime a {host} space runs on, which no such space builds as a program: the program is a module of the project that uses it
```

A JavaScript or a cpython space runs on its host's runtime, the modules of `rt/hosts/js` or
`rt/hosts/py`, which neojac compiles as the runtime under every program of such a space and never
as a program of its own: a cpython space emits nothing of such a module, and a JavaScript space
emits it as one of the runtime's files. So a space whose program would start at one, `neojac run`
of the module or a space whose `entry` names it, has no program to run, and the build stops before
it emits anything. It is reported at the module: `{module}` is its key in the runtime's archwire
and `{host}` the host of its space.

```text
rt/hosts/py/probe.jac:1:1: error[E5272]: 'hosts.py.probe' is a module of the runtime a cpython space runs on, which no such space builds as a program: the program is a module of the project that uses it
```

**Fix:** run a module of a project whose space uses what the runtime's module gives, with `--rt`
naming the runtime it is in ([Building](../../toolchain/build.md)).
