# E1615 to E1646: type parameter packs, wide text, C++ and Rust templates, C++ comparisons, C++ constructors, C++ function pointers, objects lent to C, sizeof, managed places, objects found by a field, statics written through a subclass, C++ templates deduced from a function, several C++ functions written as one name, @reads functions that change something, what markup cannot hold, and C's variadic arguments read as what `...` does not carry

A type parameter pack, `*Ts` among a function's type parameters, types the function's `*`
parameter (`*args: *Ts`) with the types of the arguments each call gives it, one by one, and each
call is compiled for them. These codes report a pack declared or used where it cannot be, and a
call that does not give it its types one by one. See
[Type parameter packs](../../language/generics.md#type-parameter-packs) (`neojac docs type parameter pack`).

E1619 reports `ptr[u16]()` or `ptr[u32]()` of a `str` that is no literal. E1620 and E1622 report a
C++ member or function template's instance that the program's build cannot make, and E1625 a Rust
generic function's. E1624 reports Jac's own `==` or `!=` of two values of C++ classes, which
would compare the Jac objects, not what C++ compares. E1621 reports a call of a C++ class that is
not its default constructor, E1635 a value lent to C by `hold` that is no counted object, E1636
`sizeof` of a type C does not lay out, E1637 an `own` binding that would take a value whose drop
runs code from a managed place, and E1638 `held[T](f=p)` where `f` is no C record field `T` keeps
in place or `p` no pointer to it. E1639 reports what is given for a C++ pointer to a function
that is no def of its signature named as it is, and E1623 the same for a C++ pointer to a member
function. E1640 reports a static written through a subclass of the class that declares it.

## E1615

```text
the type parameter pack '{pack}' is not where a pack can be: {why}
```

`{pack}` is declared or used where a pack cannot be, and `{why}` says which: a class or a type
alias declares one (a function or a method does), a function declares a second, the pack types no
`*` parameter of its function, or the pack is written elsewhere than as `*Ts`, the type of the `*`
parameter (a local typed `Ts`).

```jac
# expect: E1615 x2
def two[*Ts, *Us](*args: *Ts) -> int {
    return len(args);
}

obj Box[*Ts] {
    has n: int = 0;
}

with entry {
    print(two(1), Box().n);
}
```

**Fix:** declare one pack, on the function whose `*` parameter it types, and use the `*`
parameter (`args`, a tuple) where the values are needed. A class that holds values of several
types holds them as a `tuple` or as fields.

## E1616

```text
`*{name}` types a `*` parameter by a type parameter pack, and this function declares no pack of that name
```

A `*` parameter is typed `*{name}`, the form that names a pack, and `{name}` is no pack of the
function: an ordinary type parameter, or a name it does not declare.

```jac
# expect: E1616
def other[U, *Ts](*args: *U) -> int {
    return len(args);
}

with entry {
    print(other(1));
}
```

**Fix:** type the `*` parameter by the function's pack (`*args: *Ts`), or, for arguments of one
type, by a type (`*args: U`).

## E1617

```text
{callee} takes a type parameter pack, which each call's arguments give: it takes no type arguments
```

A call of a function with a type parameter pack writes type arguments in brackets. The pack's
types are the arguments' own, so a call gives them by its arguments alone.

```jac
# expect: E1617
def count[*Ts](*args: *Ts) -> int {
    return len(args);
}

with entry {
    print(count[int](1));
}
```

**Fix:** drop the brackets (`count(1)`), and convert an argument where it should be of another
type (`count(float(1))`).

## E1618

```text
{callee}'s type parameter pack is given by its arguments one by one, and a spread whose length is not known where it is compiled cannot give it
```

A call spreads a value whose length is known only as the program runs, a list, into a function's
pack. Each call is compiled for the types of the pack's arguments, one by one, so their number is
fixed where the call is compiled. A spread of a tuple gives one argument for each of its items,
and is accepted; a spread of the function's own `*args` is a tuple too.

```jac
# expect: E1618
def count[*Ts](*args: *Ts) -> int {
    return len(args);
}

with entry {
    held = [1, 2];
    print(count(*held));
}
```

**Fix:** pass the values one by one, or as a tuple (`count(*(1, 2))`); or give the function a
`*` parameter of one type (`def count(*args: int)`), which takes a list's spread.

## E1619

```text
{ty}() of a str is the static NUL-ended text of a string literal, and this str is no literal
```

`ptr[u16]("text")` and `ptr[u32]("text")` are a string literal's text as C's `u"text"` and
`U"text"` are: static data, UTF-16 or UTF-32, NUL-ended, made where the program is compiled. A
`str` made as the program runs has no such data, so `{ty}`, `ptr[u16]` or `ptr[u32]`, is given a
literal only. See [Strings](../../interop/c-libraries.md#strings).

```jac
# expect: E1619
with entry {
    name = "abc" + str(3);
    print(ptr[u16](name)[0]);
}
```

**Fix:** write the text as a literal (`ptr[u16]("abc3")`). Text made as the program runs is
encoded into bytes of its own, NUL-ended where C reads to a NUL
(`(name + "\0").encode("utf-16-le")`), and passed to a parameter that takes `bytes`.

## E1620

```text
the C++ class '{cls}' has no instance {name}[{args}] of its member template: the template does not take these type arguments, or one is no class or number type of C++
```

A call names an instance of a C++ class's member function template, `o.{name}[{args}](...)`, that
the program's build could not make. Each instance a program names is made by reading the module's
headers again with it asked for; this one is no instance, since the template does not compile with
these arguments, or an argument is a Jac type C++ has no type for (a `str`, a list). See
[Member function templates](../../interop/c-modules.md#member-function-templates).

<!-- example: not checked: needs the C++ header library whose Counter has the member template to<T>() -->
```jac
with entry {
    c = Counter.make(i32(7));
    print(c.to[float](), c.to[str]());
}
```

```text
main.jac:3:31: error[E1620]: the C++ class 'Counter' has no instance to[str] of its member template: the template does not take these type arguments, or one is no class or number type of C++
```

E1620 is reported where the program names another instance of the template that the build makes,
`c.to[float]()` above. Where `c.to[str]()` is the program's only instance of `to`, the class has no
member `to` at all, and the call is E1030 (`Counter has no field 'to'`).

**Fix:** give type arguments the template takes: a class of the module, a `libcxx` class or a
number type (`c.to[float]()`); for a string, a `libcxx` `std_string` where the template makes one.

## E1621

```text
calling the C++ class '{cls}' makes it by its default constructor, and {why}: a constructor is one of its make members
```

A call of a C++ class's type, `T()`, makes the object by the class's default constructor, as
`T t;` makes it in C++. Jac has no overloading, so a call of the type is that constructor alone:
it takes no arguments, and the class must have a default constructor the interface binds. `{why}`
says which of the two the call misses. A constructor that takes arguments is one of the class's
`make` members, named by its parameters (`make`, `make_i32`, `make_ptr_i8`). `{cls}` is the
class as the program writes it, an instance by its template form: `std_vector[i32]`. See
[What Jac uses of C++](../../interop/c-modules.md#what-jac-uses-of-c).

```jac
# expect: E1621
import from libcxx { std_vector }

with entry {
    v: own std_vector[i32] = std_vector[i32](u64(3));
    print(v.size());
}
```

**Fix:** call the class with no arguments where it has a default constructor
(`std_vector[i32]()`), or the `make` member of the constructor the arguments are for.

## E1622

```text
the C++ function template '{name}' has no instance {name}[{args}]: the template does not take these type arguments, or one is no class or number type of C++
```

A call names an instance of a header library's free function template, `{name}[{args}](...)`,
that the program's build could not make. Each instance a program names is made by reading the
module's headers again with it asked for; this one is no instance, since the template does not
compile with these arguments, or an argument is a Jac type C++ has no type for (a `str`, a list).
See [Function templates](../../interop/c-modules.md#function-templates).

<!-- example: not checked: needs the C++ header library whose kept is a function template -->
```jac
with entry {
    print(kept_[float](2.5), kept_[str]("x"));
}
```

```text
main.jac:2:36: error[E1622]: the C++ function template 'kept_' has no instance kept_[str]: the template does not take these type arguments, or one is no class or number type of C++
```

**Fix:** give type arguments the template takes: a class of the module, a `libcxx` class or a
number type (`kept_[float](2.5)`); for text, the member of the name's set that takes a C string
(`kept_ptr_i8("x")`), where there is one.

## E1623

```text
{given} is given for the C++ pointer to a member function '{param}' of {callee}, which takes a method of {cls} by its class ({cls}.{method_hint}), one whose parameters and result are {form}
```

A C++ member, `{callee}`, takes a pointer to a member function of the class a Jac class derives
(C++'s `int (T::*m)(int)`, as a library's table of an object's methods takes them), and what is
given for its parameter `{param}` is no method of the Jac class `{cls}` named by its class, with
the parameters and result `{form}` the pointer's type has: the object first, then the member's
parameters. `{given}` says what was given: a lambda, a bound method (`Drop().plus_size`, a method
of one object), or a method of another signature, named with its type. `{callee}` names the
member by the class C++ makes for the instance. See
[A Jac class deriving a C++ class](../../interop/c-modules.md#a-jac-class-deriving-a-c-class).

<!-- example: not checked: needs a C++ header library whose class template Pool takes a pointer to a member function of the class deriving it -->
```jac
obj Drop(Pool[Drop]) {
    override def size -> i32 {
        return i32(6);
    }

    def plus_size(x: i32) -> i32 {
        return x + self.size();
    }
}

with entry {
    print(Drop.call(Drop.plus_size, i32(5)));
    Drop.call(lambda (d: Drop, x: i32) -> i32 { return x; }, i32(5));
    Drop.call(Drop.size, i32(5));
    Drop.call(Drop().plus_size, i32(5));
}
```

```text
main.jac:12:15: error[E1623]: a lambda is given for the C++ pointer to a member function 'm' of Pool___neojac_crtp_main_Drop.call, which takes a method of Drop by its class (Drop.name), one whose parameters and result are Callable[[Drop, i32], i32]
main.jac:13:15: error[E1623]: 'Drop.size', of the type Callable[[Drop], i32] is given for the C++ pointer to a member function 'm' of Pool___neojac_crtp_main_Drop.call, which takes a method of Drop by its class (Drop.name), one whose parameters and result are Callable[[Drop, i32], i32]
main.jac:14:15: error[E1623]: a bound method is given for the C++ pointer to a member function 'm' of Pool___neojac_crtp_main_Drop.call, which takes a method of Drop by its class (Drop.name), one whose parameters and result are Callable[[Drop, i32], i32]
```

`Pool<T>::call(int (T::*m)(int) const, int x)` makes a `T` and calls `m` on it.

**Fix:** give a method of the class by its class, `Drop.call(Drop.plus_size, i32(5))`, with the
parameters and result the pointer's type has.

## E1624

```text
'{op}' of two values of the C++ classes {left} and {right} compares them as Jac objects, by identity, not as C++ compares them: write {fix}
```

`==` or `!=` compares two values of C++ classes, a C++ module's classes or `libcxx`'s, `{left}`
and `{right}` as the program writes them. Jac's own `==` of two such values would compare the
Jac objects that hold them, by identity, where C++'s compares what they hold: two iterators at one
position are equal in C++ and are two objects in Jac. So the comparison is refused when the
program compiles, and `{fix}` names what to write: `a.op_eq(b)` or `a.op_ne(b)`, C++'s own
operator, where the class binds a member `operator==` or `operator!=`, or `a is b` for the same
object, where it binds none. For a `libcxx` class whose operator is a free function template of
`std` (`std_string`'s), `{fix}` names that too: `import from libcxx { op_eq }`, each instance named
by its parameters and called with its type arguments. See
[The C++ standard library's classes](../../interop/c-modules.md#the-c-standard-librarys-classes).

```jac
# expect: E1624 x2
import from libcxx { std_string, std_vector, std_vector_iterator }

with entry {
    v: own std_vector[i32] = std_vector[i32]();
    v.push_back(i32(3));
    pos: std_vector_iterator[i32] = v.begin();
    stop: std_vector_iterator[i32] = v.end();
    walked = 0;
    while pos != stop {
        walked += int(pos.op_deref());
        pos.op_inc();
    }
    a: own std_string = std_string.make_ptr_i8("ab");
    print(walked, a == a);
}
```

```text
main.jac:9:11: error[E1624]: '!=' of two values of the C++ classes std_vector_iterator[i32] and std_vector_iterator[i32] compares them as Jac objects, by identity, not as C++ compares them: write `a.op_ne(b)` for C++'s operator!=, or `a is b` for the same object
main.jac:14:19: error[E1624]: '==' of two values of the C++ classes std_string and std_string compares them as Jac objects, by identity, not as C++ compares them: write `a is b` for the same object; C++'s operator== of these classes is a free function template of std, which `import from libcxx { op_eq }` gives, each instance named by its parameters (`op_eq_<params>[<type arguments>](a, b)`)
```

**Fix:** call C++'s operator, `while pos.op_ne(stop)`, and test the same object with `is`
(`a is a`). Two strings are compared by `std`'s operator, imported as `op_eq`, its instance for
two strings named by its parameters:
`op_eq_std_basic_string_std_basic_string[i8, std_char_traits[i8], std_allocator[i8]](a, b)`, with
`std_char_traits` and `std_allocator` imported from `libcxx` too; `op_eq_std_basic_string_ptr_T0`
compares a string with a C string. `a.compare_std_string(b) == 0`, `compare`'s member that takes a
string, says the same.

## E1625

```text
the Rust function '{name}' has no instance {name}[{args}]: its bounds do not hold for these type arguments, or one is no type Jac gives Rust
```

A call names an instance of a Rust generic function or method, `{name}[{args}](...)`, that
rustc could not make, or gives one whose type parameter is the type of an argument an argument of
a type it has no instance for (`counter.add_any("three")` of an `N: Into<u32>`, where `{args}`
is `str`). Each instance a program names, or its arguments name, is asked of rustc when the
module is read, and made for the program; this one is no instance, since a bound of the
function's type parameters does not hold for these arguments (`size_of<T>` takes a `T: Sized`,
and Rust's `str` has no fixed size), or an argument is a Jac type Rust has no type for. See
[Slices, iterators and generic methods](../../interop/rust-modules.md#slices-iterators-and-generic-methods).

```jac
# expect: E1625
import from std.mem { size_of }

with entry {
    print(size_of[u32](), size_of[str]());
}
```

**Fix:** give type arguments that meet the function's bounds: a number type, `str` where the
function takes `&str` or `AsRef<str>`, `Slice[u8]` for `&[u8]`, a Rust type of the program
(`size_of[Vec[u8]]()`).

## E1635

```text
hold() lends C a counted object, and {what} is {type}
```

`hold(x)` gives C a reference to the Jac object `x`, which `held[T](p)` takes back and
`release(p)` gives up. Only a counted object can be held so: an instance of an `obj`, `node`,
`edge` or `walker`. `{what}` is `hold()`'s argument, whose type `{type}` is a number, a str, a
struct or a C record, or `held()`'s type, a struct or a C record. See
[Objects C keeps](../../interop/pointers-and-native-memory.md#objects-c-keeps-hold-held-held_at-release).

```jac
# expect: E1635 x2
import from c {
    obj Pair {
        has a: i32,
            b: f32;
    }
}

with entry {
    p = hold(5);
    print(held[Pair](p).a);
}
```

**Fix:** lend C plain data with `pin` (`pin(5)`), or a pointer to C memory as it is; hold an
object of an `obj` (`hold(Tally())`) and take it back as its class (`held[Tally](p)`).

## E1636

```text
sizeof() takes a type C lays out (a number, a bool, a ptr, a C record, a struct of those or an array of them), and {type} is none
```

`sizeof(T)`, from `jaclang.comptime`, is the bytes C lays a `T` out in, as C's `sizeof` is. A type
C has no layout for has no size: `{type}` is an `obj`, `node`, `edge` or `walker`, whose instances
Jac counts and keeps by reference, a `str`, a collection, or a struct holding one. See
[Compile-time values](../../language/compile-time-values.md#bits-signed-and-sizeof).

```jac
# expect: E1636 x2
import from jaclang.comptime { sizeof }

obj Box {
    has n: int = 0;
}

with entry {
    print(sizeof(Box), sizeof(list[int]));
}
```

**Fix:** ask the size of what C holds: a struct of numbers (`struct Box { has n: int = 0; }`,
`sizeof(Box)` is 8), or a `ptr` where C keeps a reference to a Jac object (`sizeof(ptr)`, with
`hold`).

## E1637

```text
'{place}' is a managed place of a {cls}, whose drop runs code: an `own` binding would end the value while the place still refers to it; bind it with `own` where it is made, and move that owner
```

A value whose drop runs code (a Rust value whose drop is significant, a C++ class whose destructor
is not trivial, a class that owns a field of one) is taken from a managed place into an `own`
local, or given to an `own` or `lin` parameter. `{place}` is that place: a local or parameter with
no ownership annotation, a global, a field with none, an item of a container that does not own
its items, or a call (`'kept(...)'`) of a function whose result may be the value of one of those.
A function's result may be such a value where a `return` of it gives a field with no ownership
annotation, a global, a parameter with none, `self`, an item of a container that does not own its
items, a local that took one of those, or the result of a call that may give one. A function
declared `-> own T`, a constructor, and a function whose `return`s give only what it made or what
an owner gave up give a value an owner may take. `{cls}` is the value's class as the program
writes it. A managed place shares its
value, which ends when its last reference goes; an owner ends its value where its scope ends,
whatever else refers to it. So the place would still refer to a value that has ended. See
[Values whose drop runs code](../../language/ownership.md#values-whose-drop-runs-code-dropped-where-their-scope-ends).

```jac
# expect: E1637 x3
import from std.collections { HashSet }

obj Seen {
    has s: HashSet[u32];
}

def kept(k: Seen) -> HashSet[u32] {
    return k.s;
}

def taken(k: Seen) -> bool {
    s = HashSet[u32].new();
    t: own HashSet[u32] = s;
    u: own HashSet[u32] = k.s;
    v: own HashSet[u32] = kept(k);
    return t.is_empty() and u.is_empty() and v.is_empty();
}
```

**Fix:** bind the value with `own` where it is made, and move that owner
(`s: own HashSet[u32] = HashSet[u32].new(); t: own HashSet[u32] = s;`), or leave the binding
managed (`t = s;`), which shares the value.

## E1638

```text
held[{cls}]({field}=p) finds the object C holds by the address of that field, which must be a C record the object keeps in place, and p a ptr to that record: here {half} is {given}
```

`held[T](f=p)` is the `T` C holds whose field `f` is at the address `p`: C keeps the address of a
record inside the object, and hands it back. Check proves both halves at compile time. `{field}`
must be a field of `{cls}` whose type is a C record, which the object keeps in place (a field typed
`R | None` is a reference, and is not), and `p` a `ptr[R]` of that record's type. `{half}` is the
half that does not hold, the field or `p`, and `{given}` what the program gave there: the field
with its type (or that `{cls}` has no field of that name), or `p`'s type, a bare `ptr`, a pointer
to another record, or anything else. See
[Objects C keeps](../../interop/pointers-and-native-memory.md#an-object-found-by-a-record-it-keeps).

```jac
# expect: E1638 x2
import from c {
    obj Pair {
        has a: i32,
            b: f32;
    }
}

obj Tally {
    has n: int,
        pair: Pair;
}

with entry {
    t = Tally(n=4, pair=Pair(a=i32(3)));
    p = hold(t);
    q = addressof(t.pair);
    print(held[Tally](pair=p).n);
    print(held[Tally](n=q).n);
    release(p);
}
```

**Fix:** name a C record field the class keeps in place, and give the address of that field as a
`ptr` of its record's type: `held[Tally](pair=addressof(t.pair))`, or `held[Tally](pair=ptr[Pair](p))`
for an address C handed back as a bare `ptr`. An address `hold(x)` gave is the object's own, taken
back with `held[Tally](p)`.

## E1639

```text
'{param}' of {callee} is a C++ pointer to a function, {form}, which takes a module-level def or a static method of exactly that signature by its name: {given}
```

A C++ function or member, `{callee}`, takes a pointer to a function of C++ types for its parameter
`{param}`, whose Jac form is `{form}`: C++ keeps it and calls it later, through a function the
interface writes for the one Jac function given there. So what is given must be one function
known when the program compiles, with no captures, named as it is, of exactly that signature.
`{given}` says what was given instead: a lambda, a bound method (one object's method, which
C++ could not call without the object), a function with captures, an expression that names no
function, or a named function of another type, with its type. See
[A Jac function C++ calls back](../../interop/c-modules.md#a-jac-function-c-calls-back).

<!-- example: not checked: needs the C++ header library whose Hooks keeps a function pointer -->
```jac
def bump_by(c: Counter, step: i32) -> i32 {
    return c.bump(step * i32(2));
}

with entry {
    h = Hooks.make(i32(1));
    h.on_bump(bump_by);
    h.on_bump(lambda (c: Counter, step: i32) -> i32 { return step; });
    h.on_bump(h.bumped);
}
```

```text
main.jac:8:15: error[E1639]: 'f' of Hooks.on_bump is a C++ pointer to a function, Callable[[Counter, i32], i32], which takes a module-level def or a static method of exactly that signature by its name: a lambda
main.jac:9:15: error[E1639]: 'f' of Hooks.on_bump is a C++ pointer to a function, Callable[[Counter, i32], i32], which takes a module-level def or a static method of exactly that signature by its name: a bound method
```

A def of another module, and a static method by its class (`Bumper.by_ten`), are given as a def
of the calling module is.

**Fix:** give a def of the module by its name, of exactly the pointer's signature
(`h.on_bump(bump_by)`); where it needs a value the program has, keep that value where the def
reads it (a global, or the object C++ passes it).

## E1640

```text
a static is written through the class that declares it: write '{declaring}.{name}', not '{through}.{name}'
```

A static field `{name}` is assigned, or updated in place (`+=` and the other augmented
assignments), through `{through}`, a subclass of `{declaring}`, the class that declares it. A
class has one value of each of its statics, shared by every subclass, so a write through a
subclass's name would change the base's value while reading as if the subclass had its own.
Reading a static through a subclass (`Special.made`) is the declaring class's value, and is
allowed. In a cpython space a class is Python's class object, and a write through a subclass is
that subclass's own attribute, as in Python; see
[Static fields](../../language/fields.md#static-fields).

```jac
# expect: E1640 x2
class Made {
    static has made: int = 0;
}

class Special(Made) {}

with entry {
    Made.made = 1;
    print(Special.made);
    Special.made = 10;
    Special.made += 1;
}
```

```text
main.jac:10:5: error[E1640]: a static is written through the class that declares it: write 'Made.made', not 'Special.made'
main.jac:11:5: error[E1640]: a static is written through the class that declares it: write 'Made.made', not 'Special.made'
```

**Fix:** write the static through the class that declares it, `Made.made = 10`. Where each
subclass needs a value of its own, declare a static of its own in each subclass.

## E1641

```text
{given} is given to {callee}, a C++ function template whose template argument C++ deduces from the function given, and {why}
```

A C++ function template takes a callable, its type a template parameter C++ deduces from the
argument: a class's member template (`template <typename Hook> int bump_with(Hook hook, int by)`,
as napi's `Function::New` takes one) or a free function template (`std::call_once`). A program
calls it by the template's own name with a def or a static method,
`h.bump_with(bump_by, i32(2))` or `std_call_once(flag, started_once)`, and the program's build
makes the instance for the C++ type of that function. `{callee}` is the template as the program
wrote it (`Hooks.run`, `Pool[Drop].call`, `std_call_once`). Here the function given, `{given}`,
has no such instance, and `{why}` says why:

- a parameter or the result of the function is no C++ type (`its parameter 'why', of the type
  str, is no C++ type`): only numbers, `bool`, pointers and the library's classes cross;
- a parameter of the function is a class of a C module, given to a `std` template
  (`its parameter 'c', of the type Counter, is a class of the C module tally, which libcxx's
  instances are not made over`): `libcxx`'s instances are made over its own classes and numbers;
- the template has no instance for it: the template's definition does not compile for a
  function of that type, as when it uses the result as a number and the function gives a class,
  or when it needs the class behind an `Arg *` complete (`Arg copy = *arg;`) and is given a Jac
  object as `held_at(note)`, which crosses as `void *`.

See [A Jac function C++ calls back](../../interop/c-modules.md#a-jac-function-c-calls-back).

<!-- example: not checked: needs the C++ header library whose Hooks has the member templates run and bump_with -->
```jac
def remade_by(c: Counter, step: i32) -> Counter {
    return Counter.make(c.value() + step);
}

def named(c: Counter, why: str) -> i32 {
    return i32(len(why));
}

with entry {
    h = Hooks.make(i32(1));
    print(Hooks.run(remade_by, i32(5)));
    print(h.bump_with(named, i32(2)));
}
```

```text
main.jac:11:21: error[E1641]: 'remade_by' is given to Hooks.run, a C++ function template whose template argument C++ deduces from the function given, and the template has no instance for it: its definition does not compile for this instance of the class
main.jac:12:23: error[E1641]: 'named' is given to Hooks.bump_with, a C++ function template whose template argument C++ deduces from the function given, and its parameter 'why', of the type str, is no C++ type
```

`Hooks::run` returns `cb(c, 3) * 100 + c.value()`, which C++ cannot compute where `cb` gives a
`Counter`.

**Fix:** give a function whose parameters and result are C++ types, of the signature the
template calls it with (`def bump_by(c: Counter, step: i32) -> i32`).

## E1642

```text
'{name}' names {count} C++ functions, each given by its parameters: write one of {members}
```

A C++ library gives several functions of one name (overloads, or function templates that differ
in their parameters), and Jac names each by its parameters: `std::min` is
`std_min_T0_T0`, `std_min_T0_T0_T1` and two more. The name they share, `{name}`, is none of
them, and the program wrote it, alone or with type arguments. `{members}` lists the names to
write, the first four and how many more there are. It is reported for a C or C++ module's set of
any name, the standard library's among them. See
[C modules](../../interop/c-modules.md).

<!-- example: not checked: reports an error -->
```jac
import from libcxx { std_min }

with entry {
    print(std_min[i32](3, 7));
}
```

```text
main.jac:4:11: error[E1642]: 'std_min' names 4 C++ functions, each given by its parameters: write one of std_min_T0_T0_T1, std_min_T0_T0, std_min_std_initializer_list_T1, std_min_std_initializer_list
```

**Fix:** write the member that takes the arguments given, with its type arguments:
`std_min_T0_T0[i32](3, 7)`, which prints `3`. The import stays the set's name, `std_min`: a
member is not imported by its own name (E1145).

## E1643

```text
'{name}' is declared @reads, so calls of it may run at the same time as one another, and {why}
```

A function declared `@reads` says that calls of it may run at the same time as one another: a
model's calls of a tool in one round do ([By and sem](../../language/by-and-sem.md#tools-that-only-read-reads)).
The compiler holds the declaration to the program's own code, and reports the statement that
breaks it, in the function or in one it calls. `{name}` is the declared function and `{why}`
what the statement does: it `assigns a name outside the call or changes an object the call did
not make`, `changes its own object`, or the function `needs changing or walking a graph`. The
statement may be in a `__del__`: an object the call makes ends with the call, so its destructor
is the call's. What the function reaches in the runtime's modules and in C is not followed, nor
what a value whose class the compiler does not know does.

An object is the call's own when every value bound to its local is made there: a list, dict or
set display, a comprehension, a constructor call, `list()`, `set()`, `sorted()`, or a list
joined (`a + b`), repeated or sliced. A parameter, a global's value, what another function
returned and an item read back out of a container are not, so a change to one of them is
reported.

```jac
# expect: E1643
import from jaclang.comptime { reads }

glob asked: int = 0;

@reads
def count(word: str) -> int {
    asked += 1;
    return asked;
}

with entry {
    print(count("a"));
}
```

**Fix:** drop `@reads`, and the function's calls run one at a time, in the order they were
asked for; or keep what it changes in an object of its own, made in the call.

## E1644

```text
'{attr}' on <{tag}> is an event handler, a ref or a key, and none of those means anything in markup, which is text
```

In a native space a JSX element is `Markup`, HTML text
([JSX in a native space](../../apps/components.md#jsx-in-a-native-space-markup)). What a
component of a UI space does as it lives is not in text: `{attr}` is an event handler (`on`
followed by a capital letter, as `onClick`, or any attribute whose value is a function), `ref` or
`key`, on the element or the component `{tag}`.

```jac
# expect: E1644 x2
def save {}

with entry {
    print(<button onClick={save} key="b">Save</button>);
}
```

**Fix:** take the attribute out. A page whose element answers a click is a page of a browser
space ([Components and JSX](../../apps/components.md)); an attribute HTML reads as script, as
`onclick="..."`, is a string like any other.

## E1645

```text
<{tag}> is a void element, written with no end tag, and holds no children
```

`{tag}` is one of HTML's void elements (`area`, `base`, `br`, `col`, `embed`, `hr`, `img`,
`input`, `link`, `meta`, `source`, `track`, `wbr`), which markup writes with no end tag, and it is
given children, which HTML would put after it.

```jac
# expect: E1645
with entry {
    print(<img src="logo.png">the logo</img>);
}
```

**Fix:** write the element alone (`<img src="logo.png" alt="the logo" />`), and what it seemed to
hold after it.

## E1646

```text
the next of C's variadic arguments is read as what C's `...` carries, a 32- or 64-bit int, a float or a ptr, not {type}
```

`args.next[T]()` reads the next of C's variadic arguments as `T`, as C's `va_arg` does
([Functions of C's variadic arguments](../../interop/c-libraries.md#functions-of-cs-variadic-arguments)).
C's `...` carries an argument as its default promotions make it: a `char` or a `short` as an
`int`, a `float` as a `double`. So `T` is `i32`, `u32`, `i64`, `u64`, `int`, `float` or a `ptr`;
`{type}` is another.

```jac
# expect: E1646
def first(n: i32, *args: VaList) -> int {
    return int(args.next[i8]());
}
```

**Fix:** read the type C's `...` carries it as, and convert: `i8(args.next[i32]())`.
