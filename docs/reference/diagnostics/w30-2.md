# W3021 to W3057: lint rules and probable mistakes

Two kinds of codes share this range. The probable mistakes (W3024, W3025, W3035, W3040), Python's spellings (W3039, W3043) and a conformance's type parameters that bound nothing (W3057) are always reported. The rest are lint rules, in two groups and beside them. The group `"style"` holds the style rules (`unnecessary-else-after-return`, `nested-if-to-elif`, `simplify-return-bool`, `unnecessary-none-return` and, in W3001 to W3013, `combine-has`, `combine-glob`, `simplify-ternary`), and the group `"clean"` holds those and `strip-comments`, `strip-docstrings`, `separate-impls` and `impls-in-annex`. Every project keeps `"clean"`, and adds the rules in no group by name under `jac.toml`'s `[check.lint]`; a project of fixtures is judged only by the rules its `select` names. `neojac fmt --fix` rewrites every rule a project keeps but `too-many-params`, and Python's spellings; it leaves the probable mistakes to their author. See [Lint](../../toolchain/lint.md) (`neojac docs lint`).

A project adds a rule in no group like this:

```toml
[check.lint]
select = ["too-many-params"]
```

## W3021

```text
the `else` after a body that ends in `{exit}` is unnecessary [unnecessary-else-after-return]
```

An `if` branch ends in `return` or `raise`, and is followed by an `else`. `{exit}` is the statement that ends the branch. Nothing after it in the branch runs, so the `else` adds only indentation. Reported by the rule `unnecessary-else-after-return`, which the groups `"style"` and `"clean"` select.

<!-- example: not checked: a lint rule, and the examples are checked with none selected -->
```jac
def sign(n: int) -> int {
    if n < 0 {
        return -1;
    } else {
        return 1;
    }
}

with entry {
    print(sign(3));
}
```

**Fix:** write the `else` branch's statements after the `if`, as `neojac fmt --fix` does:

```jac
def sign(n: int) -> int {
    if n < 0 {
        return -1;
    }
    return 1;
}

with entry {
    print(sign(3));
}
```

```output
1
```

## W3022

```text
an `else` holding only an `if` is an `elif` [nested-if-to-elif]
```

An `else` block holds a single `if` statement and nothing else. Reported by the rule `nested-if-to-elif`, which the groups `"style"` and `"clean"` select.

<!-- example: not checked: a lint rule, and the examples are checked with none selected -->
```jac
def grade(score: int) -> str {
    if score >= 90 {
        return "A";
    } else {
        if score >= 80 {
            return "B";
        }
    }
    return "C";
}

with entry {
    print(grade(70));
}
```

**Fix:** write `elif`, as `neojac fmt --fix` does: `} elif score >= 80 {`.

## W3023

```text
an `if` whose branches return True and False returns its condition [simplify-return-bool]
```

An `if` returns `True` in one branch and `False` in the other. Its condition is already that bool. Reported by the rule `simplify-return-bool`, which the groups `"style"` and `"clean"` select.

<!-- example: not checked: a lint rule, and the examples are checked with none selected -->
```jac
def positive(n: int) -> bool {
    if n > 0 {
        return True;
    } else {
        return False;
    }
}

with entry {
    print(positive(1));
}
```

**Fix:** return the condition, as `neojac fmt --fix` does:

```jac
def positive(n: int) -> bool {
    return n > 0;
}

with entry {
    print(positive(1));
}
```

```output
True
```

## W3024

```text
this condition repeats an earlier one of the same if/elif chain, so its branch never runs
```

An `elif` tests a condition that an earlier branch of the same chain already tested, and the condition only reads values, so nothing between the two can change its answer. The later branch can never run. Always reported; usually a copied line whose condition was not changed.

```jac
# expect: W3024
def grade(score: int) -> str {
    if score >= 90 {
        return "A";
    } elif score >= 80 {
        return "B";
    } elif score >= 90 {
        return "A+";
    }
    return "C";
}

with entry {
    print(grade(85));
}
```

**Fix:** write the condition that was meant, or delete the branch.

```jac
def grade(score: int) -> str {
    if score >= 97 {
        return "A+";
    } elif score >= 90 {
        return "A";
    } elif score >= 80 {
        return "B";
    }
    return "C";
}

with entry {
    print(grade(85));
}
```

```output
B
```

## W3025

```text
both branches of this `if` are the same
```

The `if` and the `else` branch of an `if` statement are the same code. Whatever the condition, the same thing happens. Always reported; usually one branch was meant to differ.

```jac
# expect: W3025
def label(n: int) -> str {
    if n % 2 == 0 {
        return f"#{n}";
    } else {
        return f"#{n}";
    }
}

with entry {
    print(label(3));
}
```

**Fix:** make the branches differ as intended, or write the code once without the `if`.

## W3030

```text
'{name}' has {count} parameters, more than {threshold} [too-many-params]
```

A function, a method or a lambda takes more than 7 parameters. `{name}` is the function (`lambda` for a lambda), `{count}` its parameters and `{threshold}` the limit. Reported by the rule `too-many-params`, which is selected by name only (`select = ["too-many-params"]`). `neojac fmt --fix` does not rewrite it: grouping the parameters is the author's decision.

<!-- example: not checked: a lint rule, and the examples are checked with none selected -->
```jac
def wide(a: int, b: int, c: int, d: int, e: int, f: int, g: int, h: int) -> int {
    return a + b + c + d + e + f + g + h;
}

with entry {
    print(wide(1, 2, 3, 4, 5, 6, 7, 8));
}
```

**Fix:** group related parameters into an `obj` or a struct and pass that.

## W3035

```text
'{op}' compares identity; compare a value with a literal with '{eq}'
```

`is` or `is not` compares a value with a number or a string literal. `{op}` is the operator and `{eq}` the one to write (`==` or `!=`). `is` asks whether two references are the same object, which for a literal depends on how the values happen to be stored; Python warns about the same line. `x is None`, `x is True` and `x is False` are accepted.

```jac
# expect: W3035
def zero(code: int) -> bool {
    return code is 0;
}

with entry {
    print(zero(1));
}
```

**Fix:** compare values with `==` or `!=`: `return code == 0;`.

## W3037

```text
'-> None' on '{name}' is unnecessary: a function that declares no return type returns None [unnecessary-none-return]
```

A function that returns no value declares `-> None`. `{name}` is the function. A function with no return type returns `None` already. Reported by the rule `unnecessary-none-return`, which the groups `"style"` and `"clean"` select. A module of a `cpython` space is not judged: there `-> None` is the annotation Python reads.

<!-- example: not checked: a lint rule, and the examples are checked with none selected -->
```jac
def log(msg: str) -> None {
    print(msg);
}

with entry {
    log("a");
}
```

**Fix:** drop `-> None`, as `neojac fmt --fix` does: `def log(msg: str) {`.

## W3039

```text
getattr(x, "{name}", None) of a value whose class has '{name}' is `x?.{name}`
```

`getattr(x, "name", None)` is asked of a value whose class declares that field. `{name}` is the field. The field always exists, so the call yields `None` only when `x` is `None`, which is what the null-safe access `x?.name` says.

```jac
# expect: W3039
obj Box {
    has width: int = 1;
}

def width(b: Box | None) -> int | None {
    return getattr(b, "width", None);
}

with entry {
    print(width(Box()));
}
```

**Fix:** write `b?.width`. `neojac fmt --fix` rewrites it.

```jac
obj Box {
    has width: int = 1;
}

def width(b: Box | None) -> int | None {
    return b?.width;
}

with entry {
    print(width(Box()), width(None));
}
```

```output
1 None
```

## W3040

```text
'{name} {op} {name}' in a filter compares the field '{name}' with the '{name}' outside it; name one of them differently
```

A filter comprehension compares a field with a name of the same spelling from outside it, `owner == owner`. `{name}` is the name and `{op}` the operator. The left side is the element's field and the right side the variable outside the filter, one spelling for two things, which a reader cannot tell apart. Always reported.

```jac
# expect: W3040
node Task {
    has owner: str = "";
}

def mine(tasks: list[Task], owner: str) -> int {
    return len(tasks[?:Task, owner == owner]);
}

with entry {
    print(mine([Task(owner="a")], "a"));
}
```

**Fix:** rename the outer variable, so each side names one thing.

```jac
node Task {
    has owner: str = "";
}

def mine(tasks: list[Task], who: str) -> int {
    return len(tasks[?:Task, owner == who]);
}

with entry {
    print(mine([Task(owner="a"), Task(owner="b")], "a"));
}
```

```output
1
```

## W3043

```text
a property is declared `has {name}: T {{ getter; }}`; @{decorator} is not Jac
```

A method is marked `@property`, or `@name.setter`. `{name}` is the property and `{decorator}` the decorator written. Jac declares a computed field as a `has` with accessors. See [Fields](../../language/fields.md).

```jac
# expect: W3043
obj Box {
    has width: int = 1;

    @property
    def area -> int {
        return self.width * self.width;
    }
}

with entry {
    print(Box().area);
}
```

**Fix:** declare the field with a getter (and a setter, for `@name.setter`). `neojac fmt --fix` rewrites both.

```jac
obj Box {
    has width: int = 1;

    has area: int {
        getter {
            return self.width * self.width;
        }
    }
}

with entry {
    print(Box().area);
}
```

```output
1
```

## W3050

```text
a comment: Jac source carries none, by design; why the code is as it is goes in the commit message, and what a reader must know in the README or docs; `neojac fmt --fix` removes it, and keeps what it said in notes/<module>.md where jac.toml's [fmt] says `notes = true` [strip-comments]
```

A comment. Reported by the rule `strip-comments`, which the group `"clean"` holds, and so every project keeps, by design: Jac source carries no comments. What a comment would say belongs elsewhere: why the code is as it is in the commit message, and what a reader must know in the project's README or docs. A project whose `jac.toml` says `notes = true` under `[fmt]` keeps it in the module's notes annex, `notes/<module>.md`, under a heading for the declaration it is about (`## Cart.add`): a comment directly above a declaration, one at the end of its line and one inside its body are all about that declaration. See [The notes annex](../../toolchain/lint.md#the-notes-annex).

<!-- example: not checked: a lint rule, and the examples are checked with none selected -->
```jac
with entry {
    # Start at one.
    x = 1;
    print(x);
}
```

**Fix:** move what the comment says to the commit message or the docs, and run `neojac fmt --fix`, which deletes it. Where `[fmt]` says `notes = true`, the fix moves it into `notes/main.md` instead, under `## with entry`, and notes written by hand go there too.

## W3051

```text
a docstring: documentation lives in the project's README or docs, not in the source, by design; `neojac fmt --fix` removes it, and keeps what it said in notes/<module>.md where jac.toml's [fmt] says `notes = true` [strip-docstrings]
```

A docstring, or any string written as a statement. Reported by the rule `strip-docstrings`, which the group `"clean"` holds, and so every project keeps, by design: a project's documentation is its README and docs. A project whose `jac.toml` says `notes = true` under `[fmt]` keeps what is said of a module or a declaration in the module's notes annex, `notes/<module>.md`, the module's own docstring under its title and a declaration's under the declaration's heading. A module of a `cpython` space keeps its docstrings, which are the `__doc__` Python reads. See [The notes annex](../../toolchain/lint.md#the-notes-annex).

<!-- example: not checked: a lint rule, and the examples are checked with none selected -->
```jac
"""Counts things."""

glob limit: int = 3;

with entry {
    print(limit);
}
```

**Fix:** move what the docstring says to the README or the docs, and run `neojac fmt --fix`, which deletes it. Where `[fmt]` says `notes = true`, the fix moves it into `notes/main.md` instead, under its title `# main`.

## W3055

```text
the body of '{name}' belongs in an impl: a module reads as its declarations, by design; `neojac fmt --fix` moves the body to the module's impl annex [separate-impls]
```

A function or a method is written with its body in its declaration. `{name}` is the function. Reported by the rule `separate-impls`, for a project that keeps declarations and bodies apart, so that a module reads as its declarations: the declaration in the module, and the body in an `impl` in the module's annex. The group `"clean"` holds it, and so every project keeps it, by design. See [Impl](../../language/impl.md).

<!-- example: not checked: a lint rule, and the examples are checked with none selected -->
```jac
def twice(n: int) -> int {
    return 2 * n;
}

with entry {
    print(twice(2));
}
```

**Fix:** declare the function with `;` and write its body in an `impl`. `neojac fmt --fix` does this, moving the body into `impl/main.impl.jac`; the comments in it are removed, or kept in `notes/main.md` where `[fmt]` says `notes = true`:

```text
main.jac              def twice(n: int) -> int;
impl/main.impl.jac    impl twice(n: int) -> int { return 2 * n; }
```

## W3056

```text
{what}: a module reads as its declarations, by design; `neojac fmt --fix` moves it there [impls-in-annex]
```

An `impl` is not where the project keeps impls. `{what}` says which: `impl 'twice' belongs in its module's annex, impl/main.impl.jac` for an impl written in the module itself, or `the annex 'main.impl.jac' belongs in impl/, beside its module` for an annex file beside its module rather than in the `impl/` directory. Reported by the rule `impls-in-annex`, which the group `"clean"` holds, and so every project keeps.

<!-- example: not checked: a lint rule, and the examples are checked with none selected -->
```jac
def twice(n: int) -> int;

impl twice(n: int) -> int {
    return 2 * n;
}

with entry {
    print(twice(2));
}
```

**Fix:** move the impl into `impl/main.impl.jac`, and an annex beside its module into `impl/`. `neojac fmt --fix` moves both.

## W3057

```text
the impl conforming {type} to {iface} restates its type's parameters and bounds none of them, which says what `impl {written}` says; `neojac fmt --fix` leaves them out
```

An `impl` that conforms a generic type to an interface restates the type's type parameters and bounds none of them. `{type}` is the type, `{iface}` the interface and `{written}` the impl without them. An impl restates a type's parameters only to bound them; restated with no bound they say what leaving them out says, every instance conforming, so they are left out. See [Interfaces](../../language/interfaces.md#generic-types).

```jac
# expect: W3057
obj Shown {
    def show -> str abst;
}

struct Pair[T] {
    has a: T;
}

impl Pair[T](Shown) {
    def show -> str {
        return f"pair of {self.a}";
    }
}
```

**Fix:** leave the type parameters out, `impl Pair(Shown) { ... }`, or bound them where only the instances whose arguments meet a bound conform. `neojac fmt --fix` leaves them out.
