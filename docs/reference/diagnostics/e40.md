# E40xx: port

These codes come from [`neojac port`](../../toolchain/port.md) (`neojac docs port`), which
translates source in another language into Jac that behaves as the source does. Each refuses a
source, or one construct of it: port writes nothing for a file it refuses any part of. In a
template, `{name}` is filled in when the error is reported. A source that its own compiler
rejects is not one of these: that compiler reports it, under its own code.

## E4001

```text
port does not translate {what} yet
```

The source holds a construct outside what port translates of its language. `{what}` names it:
`Python's \`try\``, `a C pointer`, `a Rust trait`. A language's mapping page lists what port
translates (`neojac port --mapping python`); anything else is this code.

```text
$ neojac port count.py
count.py:2:5: error[E4001]: port does not translate Python's `try` yet
 2 |     try:
   |     ^
    = help: Leave this file in Python and call it from Jac (`neojac docs interop`), or rewrite this part in the mapping's terms (`neojac port --mapping python`).
```

**Fix:** keep the file in its language and use it from Jac ([Using other
languages](../../interop/index.md)), or rewrite the construct with what the mapping has.

## E4002

```text
'{name}' is called by {user}, which is not ported, and outside a project nothing gives {language} the Jac it calls
```

A C or C++ file outside a project defines the function `{name}`, and `{user}`, another source of
its C module, calls it and is not ported in this run. Outside a project nothing wires a Jac
module's functions into the C that stays, so once the file is Jac that call would have nothing to
link to. In a project the same port goes ahead: the C that stays calls the Jac module through its
wire and the header beside it ([port](../../toolchain/port.md#in-a-project)).

```text
$ neojac port shelf/stock.c
shelf/stock.c: error[E4002]: 'item_take' is called by shelf/main.c, which is not ported, and outside a project nothing gives C the Jac it calls
    = help: Port shelf/main.c in the same run, or port the two in a project (`neojac absorb`), where a C file that stays calls the Jac through its wire.
```

**Fix:** port the calling file in the same run (`neojac port shelf`), port inside a project, or
leave both in C.

## E4003

```text
port's output '{path}' is already there
```

Port would write `{path}`, and a file of that name exists, or another source of the run ports to
it. Port never writes over a file: a port that someone has since edited is not lost.

```text
$ neojac port gcd.py
gcd.py: error[E4003]: port's output 'gcd.jac' is already there
```

**Fix:** remove or move the file to port again, or write elsewhere with `-o`.

## E4004

```text
'{path}' is no source port translates: one is known by its extension, one of {extensions}
```

`neojac port` is given a file whose extension is none of the languages it translates.

```text
$ neojac port notes.txt
notes.txt: error[E4004]: 'notes.txt' is no source port translates: one is known by its extension, one of .c, .cc, .cjs, .cpp, .cxx, .h, .hpp, .js, .mjs, .py, .rs, .ts
```

**Fix:** name a source file, or a directory, which means the sources under it.

## E4005

```text
port writes no Jac yet that keeps the meaning of {what}: {meaning}
```

Port translates the construct `{what}`, but the Jac it would write means something else, and it
has no other Jac for it yet. `{meaning}` says how the two differ. Port refuses the construct
instead of writing a program that behaves differently.

```text
$ neojac port tail.py
tail.py:3:1: error[E4005]: port writes no Jac yet that keeps the meaning of module code after `if __name__ == "__main__":`: a Jac module's `with entry` code runs before its `with entry:__main__`
 3 | print("after")
   | ^
    = help: Move the code above the `if`.
```

**Fix:** the `help` line under the error says how to write the source so that it ports.

## E4006

```text
'{path}' is no source of its project: `exclude` under [project] in jac.toml leaves it out, by '{pattern}'
```

In a project, port reads a path as the project does, and `[project] exclude` in `jac.toml` says
`{path}` is none of its sources: `{pattern}` matches it or a directory it is in.

```text
$ neojac port --check tools/bump.py
tools/bump.py: error[E4006]: 'tools/bump.py' is no source of its project: `exclude` under [project] in jac.toml leaves it out, by 'tools'
    = help: Take 'tools' out of `exclude` under [project] in jac.toml if tools/bump.py is the project's source.
```

**Fix:** port a source of the project, or take the pattern out of `exclude` if the path is one.

## E4007

```text
'{path}' is compiled for no platform: its C module, {manifest}, lists it among the sources of none
```

In a project, a C or C++ source is read for the platforms its C module compiles it for, and
`{manifest}`, the module's table, lists `{path}` for none of them: a file of another platform's
build, or one whose build was recorded on platforms it is not compiled for. There is no build of
it to read it as.

**Fix:** port the file on a project that compiles it, or list it among the module's sources for
the platform it is for.

## E4008

```text
the project porting {modules} would make does not check, so nothing of it was written: the source stays, and archwire.jac and jac.toml are as they were
```

In a project, a port is one change: the Jac, the move of the source, its wires and its tables.
Port checks the project as that change would leave it, and it does not check: the errors that
come before it and say why: here a native program would take `shop.mathx`, still Python, by a
wire (E5090). `{modules}` are the
modules ported. Nothing was written.

```text
$ neojac port shop/use.py
archwire.jac:12:5: error[E5090]: neojac does not support Python modules yet
 12 |     shop.mathx ++> shop.use { gcd }
    |     ^^^^

archwire.jac: error[E4008]: the project porting shop.use would make does not check, so nothing of it was written: the source stays, and archwire.jac and jac.toml are as they were
```

**Fix:** what the errors after it say: put the module in a space whose host runs what it uses,
or port the modules it needs with it.

## E4009

```text
'{module}' is imported by {file}, which is in no space of the project: once '{module}' is Jac, that file has no module to import
```

A file of the project that no space of `archwire.jac` holds (a script beside the project's code)
imports the module `{module}`. Once it is Jac, that file is left with an import of nothing it
can load.

```text
$ neojac port shop/mathx.py
shop/mathx.py: error[E4009]: 'shop.mathx' is imported by scripts/run.py, which is in no space of the project: once 'shop.mathx' is Jac, that file has no module to import
```

**Fix:** port the importing file too, or put it in a space, where its import is a wire.

## E4010

```text
'{path}' is compiled only inside {source}, which includes it and is not ported: once '{path}' is Jac, {source} has nothing to include
```

`{path}` is a fragment of a unity build: its C module compiles it only by `{source}`'s
`#include`, and port reads it in that source's translation unit. Ported alone, it would leave the
source an `#include` of a file that is no longer there.

```text
$ neojac port native/parts/half.c
native/parts/half.c: error[E4010]: 'native/parts/half.c' is compiled only inside native/unity.c, which includes it and is not ported: once 'native/parts/half.c' is Jac, native/unity.c has nothing to include
    = help: Port native/unity.c in the same run: a unity build's source and the files it includes port together.
```

**Fix:** port the source and the files it includes in one run: `neojac port native/unity.c
native/parts/half.c`.
Ported in one run, the source and the files it includes are refused together: where port refuses
the source, each file it includes is E4010 too, with the help `native/unity.c is refused, and a
unity build's source and the files it includes port together.` Where it refuses one of the files,
the source is [E4043](#e4043).

## E4011

```text
'{path}' is a file of the C module {module}, whose table says it is another project's code (`vendored = true`): it is built as it is, and port leaves it as it is
```

In a project, a path names a file of a C module whose table in `jac.toml` says `vendored = true`:
a library's sources kept in this repository, which the project builds as they are
([C modules](../../interop/c-modules.md#the-manifest)). Port reads none of such a module, and a
directory that holds it ports without it.

```text
$ neojac port --check deps/tiny.c
deps/tiny.c: error[E4011]: 'deps/tiny.c' is a file of the C module deps, whose table says it is another project's code (`vendored = true`): it is built as it is, and port leaves it as it is
1 source refused, nothing written for it
```

**Fix:** leave the file in C. Where the code is the project's own after all, take
`vendored = true` out of its table.

## E4012

```text
'{module}' is not ported: it imports {provider}, which this run does not port, and a module ports after those it imports
```

A source imports another that the run refuses, or does not port, so its Jac would import a module
that is not there. It is held back with that one, and nothing is written for it. In a project the
run goes on with every other step of [the plan](../../toolchain/port.md#in-a-project).

```text
$ neojac port shelf
shelf/tail.py:3:1: error[E4005]: port writes no Jac yet that keeps the meaning of module code after `if __name__ == "__main__":`: a Jac module's `with entry` code runs before its `with entry:__main__`
 3 | print("after")
   | ^
    = help: Move the code above the `if`.

shelf/use.py: error[E4012]: 'shelf/use.py' is not ported: it imports shelf/tail.py, which this run does not port, and a module ports after those it imports
    = help: Port shelf/tail.py first, or in the same run once it ports.

2 sources refused, nothing written for them
```

**Fix:** make the module it imports port (here, its code moved above the `if`), then port the two
in one run, or that one first.

**A group held back.** Modules that import each other port together, as one group of the plan.
When one of them is refused for its own code, each other module of the group is E4012, naming
that one, with a help line that says they import each other; nothing of the group is written. A
module held back for more than one of its imports names one refused for its own code first, so
the error leads to the cause.

```text
$ neojac port --check shop/even.py shop/odd.py
shop/odd.py:2:1: error[E4005]: port writes no Jac yet that keeps the meaning of `from os.path import *`, of a module that is not of this project: the names it binds are those the module has as the program runs, which port cannot read
 2 | from os.path import *
   | ^
    = help: Import the names the module uses by name.

shop/even.py: error[E4012]: 'shop.even' is not ported: it imports shop.odd, which this run does not port, and a module ports after those it imports
    = help: It and shop.odd import each other, and modules that import each other port together.
the plan, each module after those it imports; a group ports together:
  1. shop.even, shop.odd (together): refused

2 sources refused, nothing written for them
```

## E4013

```text
{project} holds the change a `neojac port` stopped part-way through: what it shows is neither the project before the port nor after it, so nothing reads it until `neojac port` in it undoes that change
```

`neojac check` or `neojac build` is run in a project whose port journal
(`.jac/port/journal.json`) is still there: a `neojac port` was killed while it made a change, so
some of its files are written and others not. What the project holds is neither its state before
that port nor after it, so neither command reads it. A port that ends, or is stopped by Ctrl-C,
leaves no journal ([In a project](../../toolchain/port.md#in-a-project)).

```text
$ neojac check shop/main.jac
error[E4013]: shop holds the change a `neojac port` stopped part-way through: what it shows is neither the project before the port nor after it, so nothing reads it until `neojac port` in it undoes that change
    = help: Run `neojac port` in shop: before it reads the project it puts back what the stopped run changed.
1 error
```

**Fix:** run `neojac port` on a path of the project (`neojac port --check shop/main.jac` writes
nothing else): before anything else, it puts back what the stopped run changed, and says so. Then
check or build again.

## E4015

```text
'{path}' is compiled for {os}, where the check of the Jac it would be fails as shown: port leaves it C, which its C module builds as it is
```

A C file of a project is ported for each platform its C module compiles it for, and its Jac is
checked under each platform's OS and architecture, with the C module's interface read as that
platform's table says. The check fails on the platforms `{os}` names (`darwin and windows`, or
`linux, darwin and windows` where this platform's own check fails too), for the reasons shown
above the error, each platform's under its own variant of the Jac module (`tux.jac`,
`tux.windows.jac`). Port leaves the file C, which the module builds as it is, and writes the
rest of the run. It is the C file's counterpart of a Python module's [E4018](#e4018).

<!-- example: not checked: a run of port in a project whose C module compiles tux.c for Linux alone -->
```text
$ neojac port --check native/tux.c
native/tux.jac:2:16: error[W2001]: unknown name 'tux_base'
archwire.jac:18:37: error[E1145]: module 'native' has no 'tux_base'

native/tux.c: error[E4015]: 'native/tux.c' is compiled for linux, where the check of the Jac it would be fails as shown: port leaves it C, which its C module builds as it is
    = help: Fix what the check of linux shows above in neojac, or in the source.
the plan, each module after those it imports; a group ports together:
  1. native.tux: refused

1 source refused, nothing written for it
```

Here `tux.c` calls `tux_base`, which a header declares that Linux's table of the module does not
hold, so the module's interface for Linux has no `tux_base`.

**Fix:** what the errors above it name: here, add the header to the Linux table's `headers`.

## E4016

```text
'{source}' imports '{module}', which neojac cannot find: port checks the Jac it writes against what its source imports, so it writes nothing until that module is installed (`neojac install`) or ported in the same run
```

A Python source imports a module at its top level that is neither installed nor ported in the
same run. Port checks the Jac it writes against the modules it imports, and without the module
there is nothing to check it against. An import where code runs, in a function or in a `try` of
the module's code (the optional-dependency idiom), is not reported: a cpython space runs it as
Python does, an `ImportError` where it runs when the module is not there.

```text
$ neojac port conf.py
conf.py: error[E4016]: 'conf.py' imports 'yamlx', which neojac cannot find: port checks the Jac it writes against what its source imports, so it writes nothing until that module is installed (`neojac install`) or ported in the same run
    = help: Add the package that holds it to jac.toml and run `neojac install`, or port the module that is it in the same run.
```

**Fix:** add the package to `jac.toml` and run `neojac install`, or port the module in the same
run.

## E4017

```text
'{module}' is loaded only on a system neojac builds for no target of: no check can judge the Jac it would be, so port leaves it Python
```

A Python module of the run is imported only under a test of the platform that picks a system
neojac builds for no target of (`sys.platform.startswith("sunos")`, AIX, the BSDs). Port checks
the Jac it writes for each target whose test picks the module, under that target's operating
system and architecture ([Platforms](../../toolchain/port.md#platforms)), and no target picks this one, so nothing
could judge its Jac. It stays Python, as it was, and the module that imports it under the test
imports it as Python does. The rest of the run is written: this is a refusal of the one module,
and port exits 1.

<!-- example: not checked: a run of port in a project with a cpython space -->
```python
# shop/plat.py
import sys

if sys.platform.startswith("sunos"):
    import shop.sunonly as sun

    def cores():
        return sun.cores()
else:

    def cores():
        return 1
```

```text
$ neojac port shop/plat.py shop/sunonly.py
shop/sunonly.py: error[E4017]: 'shop.sunonly' is loaded only on a system neojac builds for no target of: no check can judge the Jac it would be, so port leaves it Python
shop/plat.py -> shop/plat.jac
shop/plat.py -> replaced-by-neojac/shop/plat.py
1 source refused, nothing written for it
```

**Fix:** none is needed: the module runs as Python where its system loads it. Leave it out of the
run to say so.

## E4018

```text
'{module}' is loaded only on {os}, whose check of the Jac it would be fails as shown: port leaves it Python, and the modules that import it under their test of the platform import it as Python does
```

A Python module of the run is imported only under a test of the platform, and the Jac port writes
of it does not check on the one system that loads it, `{os}`, for the reasons shown above the
error. On every other system nothing loads it, so its failure there is its own: it stays Python,
the modules that import it under their test import it as Python does, and the rest of the run is
written. Port exits 1.

<!-- example: not checked: a run of port in a project with a cpython space -->
```python
# shop/errs.py
import sys

if sys.platform == "win32":
    from shop import winerr as plat
else:
    from shop import posixerr as plat


def code(path):
    return plat.code(path)
```

```python
# shop/winerr.py
import os


def code(path):
    try:
        os.stat(path)
    except OSError as err:
        return err.winerror
    return 0
```

```text
$ neojac port shop/errs.py shop/winerr.py shop/posixerr.py
shop/winerr.jac:7:16: error[E1030]: OSError has no field 'winerror'
shop/winerr.py: error[E4018]: 'shop.winerr' is loaded only on windows, whose check of the Jac it would be fails as shown: port leaves it Python, and the modules that import it under their test of the platform import it as Python does
shop/errs.py -> shop/errs.jac
shop/posixerr.py -> shop/posixerr.jac
shop/errs.py -> replaced-by-neojac/shop/errs.py
shop/posixerr.py -> replaced-by-neojac/shop/posixerr.py
1 source refused, nothing written for it
```

**Fix:** what the errors above it name. Here Jac's `OSError` has no `winerror`, which CPython
gives on Windows alone; the module runs as Python there until it has.

## E4030

```text
'{name}' is a `static inline` function of {header}, a header of the project no C module holds: once '{path}' is Jac, nothing binds it
```

A C file calls a `static inline` function that a header of the project defines, and no C module
holds that header. A C module binds such a function for Jac
([C modules](../../interop/c-modules.md#the-manifest)), so once the file is Jac its call would
have nothing to call.

```text
$ neojac port --check native/count.c
native/count.c:12:27: error[E4030]: 'clamped' is a `static inline` function of include/clamp.h, a header of the project no C module holds: once 'native/count.c' is Jac, nothing binds it
 12 |     return quarter(scaled(clamped(n))) / 2;
    |                           ^
    = help: A header of the project belongs to a C module: name it in the `headers` of the module whose build reads it, or record the build (`neojac absorb --record`), which writes them.
```

**Fix:** name the header in the `headers` of the C module whose build reads it
(`headers = ["count.h", "../include/clamp.h"]`), or record the build, which writes them.

## E4043

```text
'{source}' includes {path}, which is not ported: once '{source}' is Jac, {path} is compiled nowhere
```

`{source}` is a unity build's source, and `{path}` a file its C module compiles only by
`{source}`'s `#include`. Port refuses `{path}` in this run, so it holds `{source}` back too: once
`{source}` were Jac, nothing would compile `{path}`. The two port together or not at all.

```text
$ neojac port native/unity.c native/parts/half.c
native/parts/half.c:3:5: error[E4001]: port does not translate a C assembly yet
native/unity.c: error[E4043]: 'native/unity.c' includes native/parts/half.c, which is not ported: once 'native/unity.c' is Jac, native/parts/half.c is compiled nowhere
    = help: native/parts/half.c is refused, and a unity build's source and the files it includes port together.
```

**Fix:** what refuses `{path}` is reported before this, under its own code: change that part of
`{path}`, or leave the unity build in C.

## E4044

```text
'{path}' is no source of its project: it is under {dir}, which neojac never reads as a project's source: what neojac and the ecosystems' tools write, an emitted space, or what neojac set aside in replaced-by-neojac/
```

`{dir}` is a directory no project's source is in: one whose name begins with `.`, `node_modules`,
`eco`, `target` or `dist`, a directory that holds an emitted space's `@jac`, or
`replaced-by-neojac/`, where neojac moved the files a port or `neojac absorb` replaced.

```text
$ neojac port --check replaced-by-neojac/shop/old.py
replaced-by-neojac/shop/old.py: error[E4044]: 'replaced-by-neojac/shop/old.py' is no source of its project: it is under replaced-by-neojac, which neojac never reads as a project's source: what neojac and the ecosystems' tools write, an emitted space, or what neojac set aside in replaced-by-neojac/
```

**Fix:** port the project's own source: a file set aside in `replaced-by-neojac/` is already
replaced by what stands in its place.

## E4045

```text
'{path}' is no source of its project: it is in {dir}, a {what} that jac.toml does not hold, which {manifest} builds as a dependency of the project, its files its own
```

`{dir}` holds a `cmodule.toml` or a `Cargo.toml` that `jac.toml` has no table for: a C module or
a crate the project depends on, which its own manifest builds and whose files are its own
business ([C modules](../../interop/c-modules.md), [Rust modules](../../interop/rust-modules.md)).
Port reads none of it.

```text
$ neojac port --check deps/tiny.c
deps/tiny.c: error[E4045]: 'deps/tiny.c' is no source of its project: it is in deps, a C module that jac.toml does not hold, which deps/cmodule.toml builds as a dependency of the project, its files its own
    = help: Make it the project's own: move deps/cmodule.toml into jac.toml as its [c."deps"] table.
```

**Fix:** make the module the project's own by moving its manifest into `jac.toml` as its table
(`[c."<dir>"]` or `[cargo."<dir>"]`), then port it.

## E4046

```text
'{path}' is no source of its project: it is {language} that no table of jac.toml builds, as a C module's sources or a crate's files
```

`{path}` is a C, C++ or Rust source of the project that nothing the project builds compiles: no
C module's table in `jac.toml` lists it among its `sources`, and it is in no crate. Port reads a
source as the project builds it ([port](../../toolchain/port.md#in-a-project)), and the project
builds none of it.

```text
$ neojac port --check tools/launch.c
tools/launch.c: error[E4046]: 'tools/launch.c' is no source of its project: it is C that no table of jac.toml builds, as a C module's sources or a crate's files
    = help: Name it where the project builds it: among the `sources` of the C module whose build compiles it, its [c."<directory>"] table in jac.toml, or in a crate jac.toml holds as [cargo."<directory>"].
```

**Fix:** list the source in the `sources` of the C module whose build compiles it (its
`[c."<dir>"]` table, [C modules](../../interop/c-modules.md#the-manifest)), then port it.
