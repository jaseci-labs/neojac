# E2240 to E2345: imports in code, a place's plugins, defaults, JavaScript classes, unions, bit-fields, crates, comptime if, Python names, quoted paths, JavaScript's faces, classes over values, TypeScript faces, C tags, C++ bases, async generators and a package's browser spaces

These codes hold a declaration to what its form means: what an import in a code body binds, where
Python's method wrappers stand among a cpython method's decorators, a module's one default, what a
class JavaScript makes may do before its object exists, how a union is made, where a bit-field may
be, which name a Rust crate or a C module takes, what a `comptime if` among declarations may test,
which Python name a module has, where a module's path is quoted, which globals JavaScript keeps as
they stood, what a class over a value derives from, what a module's TypeScript face declares,
which records have a C tag, and where a Jac class deriving a C++ class runs its base's
constructor. In a template, `{name}` is filled in when the error is reported.

## E2240

```text
'{name}' is brought into '{module}' by an import in a code body, which starts its module where it runs: use it after that import, in its body
```

`{name}` is bound by an `import` in a function or other code of the module `{module}`, and is
used outside that body, or in it before the import. An import in a code body starts its module
where it runs, so its names are the body's, from the import on, as a Python import in a function
binds local names. See [Modules](../../language/modules.md#an-import-in-a-code-body).

<!-- example: not checked: needs the file helper.jac beside it -->
```jac
def shout(s: str) -> str {
    import from helper { loud }
    return loud(s);
}

with entry {
    print(shout("hi"), loud("x"));
}
```

reports, at the second `loud`:

```text
main.jac:7:24: error[E2240]: 'loud' is brought into 'main' by an import in a code body, which starts its module where it runs: use it after that import, in its body
```

**Fix:** import the name where it is used as well, or import it at the module's top level, where
it is the module's.

## E2241

```text
'{name}' is decorated by '{deco}', which marks where among its decorators Python makes it a {wrapper}: only a `{form}` is made one
```

In a cpython space, `@builtins.staticmethod` or `@builtins.classmethod` among a method's
decorators says where Python wraps it, and `{name}` is a method of another kind. `{wrapper}` is
the wrapper and `{form}` the method that has it: a `static def` is a `staticmethod`, a
`class def` a `classmethod`. See
[Classes and decorators in a cpython space](../../interop/python-classes.md#decorators).

<!-- example: not checked: runs in a cpython space -->
```jac
import builtins;

obj Odd {
    @builtins.staticmethod
    def plain -> int {
        return 1;
    }
}
```

**Fix:** declare the method `static def plain`, or drop the decorator.

## E2242

```text
the place '{place}' provides no plugin for `{abstraction}`, which this program uses and its project leaves to the place it is built for: the place's [provides] names one, `{abstraction} = "<plugin>"`
```

A program is built for a place, and uses an abstraction that neither its project names a plugin
for nor the place's `[provides]` does. `{place}` is the place's name and `{abstraction}` the
abstraction. It is reported at the place's `[provides]`
([Plugins](../../apps/plugins.md#the-place-a-program-is-built-for)).

```toml
[project]
name = "edge"
kind = "place"

[provides]
store = "sqlite"
```

reports, for a program that serves and so has callers, `auth`:

```text
edge/jac.toml:5:1: error[E2242]: the place 'edge' provides no plugin for `auth`, which this program uses and its project leaves to the place it is built for: the place's [provides] names one, `auth = "<plugin>"`
```

**Fix:** have the place provide one, `auth = "accounts"`; or name one in the project's own
`jac.toml`, `[auth]` `plugin = "accounts"`, which holds wherever it is built.

## E2250

```text
module '{module}' marks '{first}' its default, and '{second}' as well: a module has one default
```

Two declarations of the module `{module}` are marked `default`. A module's default is the one
value `import from m { default as d }` binds. See
[Modules](../../language/modules.md#a-modules-default).

```jac
# expect: E2250
default def first -> int {
    return 1;
}

default def second -> int {
    return 2;
}
```

**Fix:** keep `default` on one declaration.

## E2251

```text
{name} derives from a JavaScript class and so from nothing else
```

On a JS host, the class `{name}` lists a JavaScript class among its bases (a global such as
`Error`, or a class an npm package exports) beside another base. JavaScript makes the object of a
class with a JavaScript base, and a JavaScript class has one base. See
[npm and Node](../../interop/npm.md#a-class-with-a-javascript-base).

<!-- example: not checked: runs in a node space -->
```jac
obj Mine {}

class Both(Error, Mine) {}
```

**Fix:** derive from the JavaScript class alone, and hold what the other base gave as a field.

## E2252

```text
'{name}.init' reads self before its super.init(...) call: JavaScript makes the object there, and a constructor reads `this` only after `super(...)`
```

The class `{name}` derives from a JavaScript class, so its `init` is a JavaScript constructor and
its `super.init(...)` is `super(...)`, which makes the object. A statement before that call reads
or sets `self`, which does not exist yet. See
[npm and Node](../../interop/npm.md#a-class-with-a-javascript-base).

<!-- example: not checked: runs in a node space -->
```jac
class Early(Error) {
    has at: int = 0;

    def init(m: str) {
        self.at = 1;
        super.init(m);
    }
}
```

**Fix:** call `super.init(...)` first, then use `self`: arguments may be worked out before it.

## E2253

```text
'{name}.init' must call super.init(...) once, as a statement of its own body: {name} derives from a JavaScript class, which makes the object there
```

The `init` of `{name}`, a class with a JavaScript base, calls `super.init(...)` more than once, not
at all, or inside another statement (an `if`, a loop, a lambda). The call is the constructor's
`super(...)`, which makes the object, and it runs once on every path. See
[npm and Node](../../interop/npm.md#a-class-with-a-javascript-base).

<!-- example: not checked: runs in a node space -->
```jac
class Twice(Error) {
    def init(m: str) {
        if m {
            super.init(m);
        }
        super.init(m);
    }
}
```

**Fix:** call `super.init(...)` once, as a statement of `init`'s own body, and choose its
arguments before it: `super.init(m if m else "unknown");`.

## E2260

```text
a union is made from at most one of its fields, given by name, and '{union}' is given {given}
```

A union is made with more than one field, or with a field given by position. `{union}` is the
union and `{given}` what it was given. A union's fields share their memory, so it is made zeroed
and then from the one field named. See [Structs](../../language/structs.md#unions).

```jac
# expect: E2260 x2
union Word {
    has whole: u32,
        half: u16;
}

with entry {
    print(Word(whole=u32(1), half=u16(2)).whole, Word(u32(1)).whole);
}
```

**Fix:** name one field: `Word(whole=u32(1))`.

## E2261

```text
the field '{name}' of the union '{union}' has a default: a union is made zeroed, and then from the one field given
```

A union's field has a default. No one field's default could stand, since every field is the same
memory.

```jac
# expect: E2261
union Word {
    has whole: u32,
        half: u16 = 0;
}

with entry {
    print(Word().whole);
}
```

**Fix:** drop the default, and give the field where the union is made: `Word(half=u16(7))`.

## E2262

```text
the field '{name}' of '{record}' is a bit-field, and only a struct, a union or a C record has bit-fields
```

A field of an `obj`, a `node`, an `edge` or a `walker` has a width after its type. A bit-field
packs into its unit as C lays it out, and only a value laid out as C's is (a struct, a union, or a
C record declared in `import from c` or a C module's interface) holds one. See
[Structs](../../language/structs.md#bit-fields).

## E2263

```text
the bit-field '{name}' is {width} bits wide, and its type {type} is no integer that wide
```

A bit-field's type is an integer type, or `bool`, of at least its width. `{name}` is the field,
`{width}` its width and `{type}` its type.

```jac
# expect: E2262, E2263 x2
import from c {
    obj Packed {
        has ready: u32: 1,
            ratio: f32: 4,
            wide: u8: 9;
    }
}

obj Plain {
    has flag: u32: 1 = 0;
}

with entry {
    print(Packed(ready=u32(1)).ready, Plain().flag);
}
```

**Fix:** give a bit-field an integer type that holds its width (`wide: u16: 9`), and declare one
only in a struct, a union or a C record.

## E2264

```text
the bit-field '{name}' is 0 bits wide, and only a bit-field named _, which pads, has no width
```

A named field has the width 0. A bit-field of no width holds nothing: it closes the unit it is
in, so that what follows starts at the next boundary of its type, as C's `unsigned : 0;` does, and
C gives it no name. `{name}` is the field.

```jac
# expect: E2264
struct Header {
    has kind: u8: 3 = 0,
        gap: u8: 0,
        flags: u8: 5 = 0;
}

with entry {
    print(Header().kind);
}
```

**Fix:** name the field `_`: `_: u8: 0`.

## E2265

```text
a bit-field named _ only pads '{record}': it takes no value
```

A bit-field named `_` has a default. It only pads: no program reads it, and it is not given where
the record is made. `{record}` is the struct or record.

```jac
# expect: E2265
struct Header {
    has kind: u8: 3 = 0,
        _: u8: 5 = 0;
}

with entry {
    print(Header().kind);
}
```

**Fix:** drop the default: `_: u8: 5`.

## E2270

```text
'{name}' is both {foreign} and a Jac or Python module: rename {which}
```

One key names two modules: `{foreign}`, a foreign module, and a Jac or Python module of the
program. `{which}` says what to rename.

- **A Rust crate this module names**: a Jac file of a Rust crate imports from `{name}`, a
  dependency of the crate, and a Jac module or a Python module of that name is found too. (A
  module of the program named `std`, `core` or `alloc` is not this: it wins over Rust's crate.)
  See [Rust modules](../../interop/rust-modules.md).
- **A C module of the project**: a wire names `{name}`, which is a C module's table's `name` and
  also a Jac or Python module's key; or a wire names a Jac or Python module `{name}` beside a
  directory of the same name holding a C module that names no `name` and lists a system header.
  See [The manifest](../../interop/c-modules.md#the-manifest).

**Fix:** rename what `{which}` names: the Jac or Python module, or the C module by its table's
`name`.

## E2290

```text
a `comptime if` among declarations is decided before any name is bound, so it tests target()'s fields, literals and hasattr() of a module this module imports, not {what}
```

A `comptime if` among a module's declarations or an archetype's members tests `{what}`, something
other than what the build targets or what a module declares. It is decided before any name of the
program has a value, so it tests `target()`'s fields (`target` imported from `jaclang.comptime`),
literals, `hasattr(M, "name")` of a module `M` this module imports, and the operators between
them. See
[comptime if](../../language/compile-time.md#among-declarations-and-members).

```jac
# expect: E2290
glob LINUX: bool = True;

comptime if LINUX {
    def kernel -> str {
        return "linux";
    }
}
```

**Fix:** test the target: `comptime if target().os == "linux"`, with
`import from jaclang.comptime { target }`.

## E2300

```text
{path} and {other} are both the Python module {name}: a dot in a part of a module's path is '_' in its Python name, as pytest names such a module, so rename one of them
```

Two modules of one cpython program have one Python name. A module's Python name is its path's
parts joined by `.`, and Python cannot name a module whose name holds a dot within a part: a dot in
a part (`pair.half.jac`, a module named by its quoted path `"pair.half"`) is `_` in its Python
name, `pair_half`, as pytest's importlib mode names such a module. Where another module of the
program is `pair_half.jac`, both would be the module `pair_half`. See
[Modules](../../language/modules.md).

<!-- example: not checked: needs two modules of one cpython space -->
```jac
# pair.half.jac and pair_half.jac beside main.jac, in a cpython space
with entry {
    print(halved(4), half_of(4));
}
```

```text
pair_half.jac:1:1: error[E2300]: pair_half.jac and pair.half.jac are both the Python module pair_half: a dot in a part of a module's path is '_' in its Python name, as pytest names such a module, so rename one of them
```

**Fix:** rename one of the two files.

## E2301

```text
hasattr({name}, ...) in a `comptime if` among declarations asks what {path} declares, and that module's own declarations are being decided by a `comptime if` that asks the same of this module: the two decisions wait on each other
```

A `comptime if` among a module's declarations that tests `hasattr({name}, ...)` is decided once
`{name}` is loaded, by what it declares; `{name}`'s own declarations are decided by a `comptime
if` that asks `hasattr` of this module. Neither can be decided first. See
[hasattr of a module](../../language/compile-time.md#hasattr-of-a-module).

<!-- example: not checked: needs two modules that import each other -->
```jac
# left.jac
import from . { right }

comptime if hasattr(right, "second") {
    def first -> int {
        return 1;
    }
}

# right.jac
import from . { left }

comptime if hasattr(left, "first") {
    def second -> int {
        return 2;
    }
}
```

```text
right.jac:3:13: error[E2301]: hasattr(left, ...) in a `comptime if` among declarations asks what left.jac declares, and that module's own declarations are being decided by a `comptime if` that asks the same of this module: the two decisions wait on each other
```

**Fix:** let one of the two decide by the target (`target().os`), or move the declarations both
ask about into a third module that asks neither.

## E2310

```text
"{path}" names a module whose path is all identifiers: a quoted path names a module only where a part of its path is no identifier, and this one is named {module}
```

An import, an `include` or a wire names a module by a quoted path, `"{path}"`, and every part of
the module's path is an identifier: its file's stem (`util.jac`) and each directory on the way to
it. A quoted path is for a module a dotted name cannot say, where a part of its path is no
identifier (`sqlite-error.jac`, `types.gen.jac`, a file in `gen.v2/`); every other module has one
name, its dotted one, `{module}`. See
[A module whose name is no identifier](../../language/modules.md#a-module-whose-name-is-no-identifier).

<!-- example: not checked: needs the file util.jac beside it -->
```jac
import from "./util" { two }

with entry {
    print(two());
}
```

```text
main.jac:1:13: error[E2310]: "./util" names a module whose path is all identifiers: a quoted path names a module only where a part of its path is no identifier, and this one is named .util
```

A wire, a layer's item and a space's item are held to the same rule, from the archwire's
directory: `"util" ++> main { two }`, `layer util { "util"; }` and `space work: native { "util"; }`
are E2310 at the quoted name, and `util ++> main { two }` is the wire; `"gen/types.gen" ++> main
{ Row }`, `layer gen { "gen/types.gen"; }` and `space gen: node { "gen/types.gen"; }` name
`gen/types.gen.jac`, which no dotted name can. A space's quoted item that is a tree of `jac.toml`
is that tree, not a module, and is not held to it.

**Fix:** write the dotted name the message gives: `import from .util { two }`, and in a wire
`util`.

## E2311

```text
'{name}' of {module} is assigned after its declaration, and {file} imports it: JavaScript takes {what} as it stands once the module has started, and would keep the first
```

A JavaScript file of the space imports `{name}` of the Jac module `{module}`, and the program
assigns `{name}` again after its declaration: in a function, through the module (`m.{name} = f`),
by a walrus or an augmented assignment. The module's forwarder gives JavaScript a global of a
function type through its face, and the module's `default`, as each stands once the module has
started (an ES module cannot export a getter), so the file would keep the first value while Jac
went on with the second. A global of any other type is a live binding, and a global no JavaScript
file imports is the module's own: either may be assigned. See
[A project's own JavaScript](../../interop/npm.md#a-projects-own-javascript).

<!-- example: not checked: needs kit/echo.js, which imports scale from maker.js, in a node space -->
```jac
def twice(x: int) -> int {
    return x * 2;
}

def thrice(x: int) -> int {
    return x * 3;
}

glob scale: Callable[[int], int] = twice;

def swap {
    scale = thrice;
}
```

```text
maker.jac:12:5: error[E2311]: 'scale' of maker is assigned after its declaration, and kit/echo.js imports it: JavaScript takes a global of a function type through its face as it stands once the module has started, and would keep the first
```

**Fix:** keep the function in a global JavaScript does not import, and give JavaScript a function
that calls it (`def scaled(x: int) -> int { return scale(x); }`); or hold it in a global of
another type, an object with the function as a field, which JavaScript reads live.

## E2312

```text
{name} derives from {base}, which is {type}: a class derives from a class, or on a JS host from a value of type any, which JavaScript makes it over
```

On a JavaScript host a class's base may be a global that holds a value, as a JavaScript class
`extends` an expression: JavaScript makes the class over the value it holds where the class's
statement runs ([A class over a value](../../interop/npm.md#a-class-over-a-value)). The global
must be of type `any`, what JavaScript is handed as it is; `{base}` is of type `{type}`, which
no class derives from. Natively, and in a cpython space, a base is a class, and a name that is
none is E2018.

<!-- example: not checked: on a node space -->
```jac
glob Size: int = 3;

obj Sized(Size) {}
```

```text
main.jac:3:11: error[E2312]: Sized derives from Size, which is int: a class derives from a class, or on a JS host from a value of type any, which JavaScript makes it over
 3 | obj Sized(Size) {}
   |           ^^^^
```

**Fix:** derive from a class, or declare the global `any` where it holds a JavaScript class or
a function JavaScript constructs (`glob Plain: any = globalThis.Set;`).

## E2313

```text
{face}, the TypeScript face of {module}, declares '{name}', which the module does not give
```

A `.d.ts` beside a Jac module of its stem is the module's face to TypeScript
([A project's own JavaScript](../../interop/npm.md#a-projects-own-javascript)), and it is held
to the module, name by name: TypeScript reads it as `neojac check` checks the space, and each
name it declares must be one the module gives JavaScript. `{name}` is declared there and the
module gives no such name: it has none, or it is `:priv`. A face that declares a name the
module lacks would let TypeScript accept an import that fails where it runs. The error is
reported at the module's first line, since the face is TypeScript's to read.

<!-- example: not checked: needs kinds.d.ts beside it, in a node space -->
```jac
def twice(x: int) -> int {
    return x * 2;
}
```

```ts
// kinds.d.ts
export declare function twice(x: number): number;
export declare function thrice(x: number): number;
```

```text
kinds.jac:1:1: error[E2313]: kinds.d.ts, the TypeScript face of kinds, declares 'thrice', which the module does not give
 1 | def twice(x: int) -> int {
   | ^^^^^^^^^^^^^^^^^^^^^^^^^^
```

**Fix:** remove the declaration from the face, or give the name in the module.

## E2314

```text
{face}, the TypeScript face of {module}, does not declare '{name}', which the module gives
```

The module gives JavaScript `{name}`, a public function, class, global or type, and its face does
not declare it. Every name the module's forwarder gives is in its face, so that TypeScript sees
what JavaScript is given. A `:priv` name is the module's own, and needs no declaration.

<!-- example: not checked: needs kinds.d.ts beside it, in a node space -->
```jac
def twice(x: int) -> int {
    return x * 2;
}

glob LIMIT: int = 10;
```

```ts
// kinds.d.ts
export declare function twice(x: number): number;
```

```text
kinds.jac:1:1: error[E2314]: kinds.d.ts, the TypeScript face of kinds, does not declare 'LIMIT', which the module gives
 1 | def twice(x: int) -> int {
   | ^^^^^^^^^^^^^^^^^^^^^^^^^^
```

**Fix:** declare the name in the face (`export declare const LIMIT: number;`), or make it
`:priv` where JavaScript has no use for it.

## E2315

```text
{face}, the TypeScript face of {module}, declares '{name}' as {kind}, which the module gives as {given}
```

The face declares `{name}` as one kind of thing and the module gives it as another: a value
against a type. What is compared is what is a value in each, so a class the module gives is a
value, and a face that declares it as an `interface` or a `type` alone says JavaScript has no
such value. A class declared as a class, or a namespace merged with a value, is no mismatch.

<!-- example: not checked: needs kinds.d.ts beside it, in a node space -->
```jac
obj Box {
    has n: int = 0;
}
```

```ts
// kinds.d.ts
export interface Box {
    n: number;
}
```

```text
kinds.jac:1:1: error[E2315]: kinds.d.ts, the TypeScript face of kinds, declares 'Box' as a type, which the module gives as a class
 1 | obj Box {
   | ^^^^^^^^^
```

**Fix:** declare it as what the module gives (`export declare class Box { n: number; }`).

## E2325

```text
'{tag} as {name}' names a record in Jac other than by its C tag, and only a C record an `import from c` block declares has a C tag
```

`obj {tag} as {name}` declares a C record `{tag}` that the program names `{name}`, for a record
whose tag is also a function's or a global's name in C (`struct stat` and `stat()`). The `as` is
written on an archetype that is no C record: a Jac struct, object or class, or one outside an
`import from c` block. It has no C tag to keep apart from its name. See
[A record named in Jac other than by its tag](../../interop/c-libraries.md#a-record-named-in-jac-other-than-by-its-tag).

```jac
# expect: E2325
struct point as spot {
    has x: int = 0;
}
```

**Fix:** name the archetype once (`struct spot { ... }`); declare a C record under another name
inside an `import from c` block.

## E2335

```text
{cls} derives the C++ class {base}, whose constructor runs as `super.{name}(...)`, the first statement of its init: here it is {where}
```

A Jac class deriving a C++ class makes its C++ part with `super.init(args)` (`super.init_<tail>`
for one of several constructors), as C++ runs a base's constructor before the derived body. The
call stands as the first statement of `init`, once. Where `init` writes none, or the class has no
`init`, the base's constructor that takes no arguments makes the part. `{where}` says what is
wrong instead: the call stands after another statement (a second `super.init` is after the
first) or in another method, or it is missing and the base has no constructor that takes no
arguments. See
[A Jac class deriving a C++ class](../../interop/c-modules.md#a-jac-class-deriving-a-c-class).

<!-- example: not checked: needs the C module whose figures.hpp declares Figure -->
```jac
obj Square(Figure) {
    has side: float;

    def init(side: float) {
        self.side = side;
        super.init(i32(4));
    }
}
```

```text
main.jac:6:9: error[E2335]: Square derives the C++ class Figure, whose constructor runs as `super.init(...)`, the first statement of its init: here it is after another statement
 6 |         super.init(i32(4));
   |         ^^^^^^^^^^^^^^^^^^
```

```text
main.jac:4:5: error[E2335]: Square derives the C++ class Figure, whose constructor runs as `super.init(...)`, the first statement of its init: here it is missing, and Figure has no constructor that takes no arguments
 4 |     def init(side: float) {
   |     ^^^^^^^^^^^^^^^^^^^^^^^
```

**Fix:** make `super.init(...)` the first statement of `init`, and the only one, with the
arguments one of the base's constructors takes.

## E2336

```text
{cls} derives {base}, which C++ makes with init's arguments: each parameter of init is a number, a ptr or a C++ class taken by &, and each argument of its super.init is one of init's parameters, passed as it is; here it is {what}
```

A C++ class template may make the class it is made with (`new T(seed)`, as a library that keeps
objects of its users' classes does), and a Jac class deriving it, `obj Kid(Keeper[Kid])`, is then
made by C++ too: C++'s `new T(seed)` runs the obj's `init` with those arguments. C++ constructs its
base first, with what `super.init` gives it, before any of `init` has run, so each argument of
`super.init` is one of `init`'s parameters, named as it is, each once. And C++ must be able to
give `init` each of its parameters: a number, a `ptr`, or a C++ class taken by `&`. `{what}` says
what it is instead: an expression that is not a parameter, a parameter given a second time, or a
parameter of a type C++ cannot give. See
[C++ making the Jac object](../../interop/c-modules.md#c-making-the-jac-object).

<!-- example: not checked: needs the C module whose tally.h declares Keeper and Sprout -->
```jac
obj Kid(Keeper[Kid]) {
    has seed: int = 0;

    def init(seed: i32) {
        super.init(seed + i32(1));
        self.seed = int(seed);
    }
}

obj Shoot(Sprout[Shoot]) {
    has w: int = 0;

    def init(w: &Weight, why: str) {
        super.init(w);
        self.w = int(w.value());
    }
}
```

```text
main.jac:5:20: error[E2336]: Kid derives Keeper[Kid], which C++ makes with init's arguments: each parameter of init is a number, a ptr or a C++ class taken by &, and each argument of its super.init is one of init's parameters, passed as it is; here it is an expression that is not a parameter
main.jac:13:26: error[E2336]: Shoot derives Sprout[Shoot], which C++ makes with init's arguments: each parameter of init is a number, a ptr or a C++ class taken by &, and each argument of its super.init is one of init's parameters, passed as it is; here it is the parameter why, of the type str
```

`Sprout<T>::grow` runs `new T(weight)`, lending a `Weight` it made: `w: &Weight` takes it, and
`why: str` is nothing C++ gives.

`{base}` is the base as the program writes it, by its template form (`Keeper[Kid]`).

**Fix:** pass `init`'s parameters to `super.init` as they are, and compute what else the base
needs in `init`'s body after it: `super.init(seed);`, then `self.seed = int(seed) + 1;`. Give
`init` only the parameters C++'s `new T(...)` passes, and set the rest after it is made.

## E2337

```text
'yield from' in an async function: an async generator yields each item itself
```

`yield from` hands a generator's iteration to another iterable. An async generator, an `async`
function declared to return `AsyncIterator[T]`, has no such form, as Python's has none: it yields
each item itself. In an `async` function that is not an async generator, `yield from` is no more
allowed.

```jac
# expect: E2337
async def inner -> AsyncIterator[int] {
    yield 1;
}

async def items -> AsyncIterator[int] {
    yield from inner();
}

with entry {
    print(items());
}
```

**Fix:** yield each item of the other in an `async for`.

```jac
async def inner -> AsyncIterator[int] {
    yield 1;
}

async def items -> AsyncIterator[int] {
    async for x in inner() {
        yield x;
    }
}

with entry {
    print(items());
}
```

## E2340

```text
the archwire.jac of {package} declares the app '{app}': a package declares browser spaces, and the project that depends on it declares the apps that serve them
```

A package's `archwire.jac` may declare browser spaces, which every app whose program loads one of
the package's modules builds and serves ([A package's browser spaces](../../apps/archwire.md#a-packages-browser-spaces)).
Which apps a project has, what each runs and serves, is the project's to say, so a package declares
none. It is reported as an app that loads the package is built.

<!-- example: not checked: needs a package beside the project that depends on it -->
```jac
graph spaces {
    space look: browser { entry look_main; pages.*; }
    app shown { run look; }
}
```

**Fix:** take the `app` out of the package's archwire. A project that depends on the package gets
its pages without naming them.

## E2341

```text
the space '{space}' of {package} has no base: a package's browser space is served at the path its own jac.toml gives it, `[spaces.{table}] base`
```

A project's browser space is served at `/` unless its `jac.toml` says otherwise. A package's space
is served beside the spaces of every project that depends on it, so it names its path itself: its
own `jac.toml` gives it a `base`, a path that begins with `/`.

**Fix:** give the space its path in the package's `jac.toml`:

```toml
[spaces.look]
base = "/lib/"
```

## E2342

```text
{first} is served at {base} and {second} at {other}: a package's browser space answers every path under its base, so no other served space's base is the same as it or under it
```

An app serves each of its spaces at its base, the longest base first. A package's space answers
every path under its base (a mailed link, an address another service sends a person back to), so
no other space an app serves may take a path of it: no space's base is the same as a package
space's, and none is under it. A package's base may be under a project's (stdjac's sign-in pages
at `/__jac/auth/` are under a project's space at `/`), but not under another package's.

**Fix:** serve the project's space, or one of the two packages' spaces, at a base outside the
other's.

## E2343

```text
{package} declares the space '{space}' on {host}: a package's space is a browser space, which an app that depends on the package serves, and a space of any other host is a project's
```

What a package holds for a program's own host is its modules, which the program loads; what it
holds for a browser is a browser space, built and served by the apps that depend on it. A space on
any other host would be a program of its own, which only a project's apps run.

**Fix:** declare the space as `browser`, or take it out and leave its modules unplaced, for the
programs that import them.

## E2344

```text
{module} is a module of the space '{space}' of {package}, and this program, of {program}, loads it: a package's space is its pages, which only the space's own build loads
```

A module a package's space holds is a page of the package, built into JavaScript with the rest of
the space. A program of a project that depends on the package, its native or cpython space, would
otherwise take it as a module of another space, to be called across a network the package's pages
are never served on.

**Fix:** import what the program needs from a module of the package that no space holds, and keep
the space's modules to its pages.

## E2345

```text
making a {cls} runs {what}, which is code of the space '{space}' that declares it: a module of another space makes such an object only when that is its fields alone, each with no default or a constant one. Ask the space for one instead, with a function it gives
```

A class wired from another space is its type on both sides: each side has its fields, and what a
crossing sends is made of them. A module makes an object of such a class where it is, to send it
or to keep it, when making it needs nothing of the space that declares it: its fields, each given
or left to a default that is a constant (a number, a string, a boolean, `None`, a member of an
enum, or a list or tuple of those). An `init`, a `postinit`, and a default that is any other
expression are that space's code, which this program does not hold.

<!-- example: not checked: two modules of two spaces, with the archwire that wires them -->
```jac
obj Task {
    has title: str,
        done: bool = False,
        id: str = next_id();
}
```

A page that is wired `Task` from this module and writes `Task(title="t")` is refused: `next_id`
runs where `Task` is declared.

**Fix:** give the space a function that makes one, and call it (`t = await new_task("t");`), or
make the default a constant and set the field where the object arrives.
