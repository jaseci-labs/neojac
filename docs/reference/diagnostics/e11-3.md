# E1171 to E1199: expressions, edge references and assignment

These codes are reported for an expression used in a way its type does not allow: a `do` block
that gives a value on some ways out and none on another, a match over a sum that leaves members
out, a sum or a member of one named where it is no value, a call that gives nothing used as a value, an edge reference that starts or ends at something that is not a node, an
assignment to something that cannot change, and a generic call whose type arguments cannot be
worked out.

## E1171

```text
a do block gives a value on every way it is left, or on none: {what} leaves it without one
```

A `do` block gives a value by its final expression or by a `break:name value`, and one of its ways
out gives none: `{what}` is `its end`, when the end of its statements can be reached with no final
expression, or `'break:name;'`, a break that names it with no value.

```jac
# expect: E1171
def sign(n: int) -> int {
    return do:s {
        if n > 0 {
            break:s 1;
        }
        if n < 0 {
            break:s -1;
        }
    };
}
```

**Fix:** give a value on every way out, here a final expression: `... break:s -1; } 0 };`. See
[Control flow](../../language/control-flow.md#do-blocks).

## E1172

```text
this match over {sum} leaves out {members}: give each a case, or end with `case _:`
```

A `match` whose subject is a sum has no case for some of its members and no case that takes
what is left. `{sum}` is the sum and `{members}` the members no case covers. A case covers its
member when it has no guard and its sub-patterns take every value, so a guarded case covers
nothing whole: a value of a member left out would match no case, which a sum's match does not
allow.

```jac
# expect: E1172
enum Shape {
    Circle(r: float),
    Rect(w: float, h: float),
    Empty,
}

def area(s: Shape) -> float {
    match s {
        case Shape.Circle(r):
            return 3.0 * r * r;
        case Shape.Rect(w, h) if w > 0.0:
            return w * h;
    }
    return 0.0;
}
```

**Fix:** give each member a case, or end with one that takes the rest: `case _: return 0.0;`. See
[Enums](../../language/enums.md#sums-members-that-hold-fields).

## E1173

```text
{what} needs a value
```

A call to a function that returns nothing is used where a value is required. `{what}` is the
place: `a condition`, `'and'`, `'or'` or `bool()`. A function declared without `->` returns
`None`, which may be printed or compared with `is None`, but its result is never something to test
for truth: such a test would always take the same branch.

```jac
# expect: E1173
def note(s: str) {
    print(s);
}

with entry {
    if note("a") {
        print("noted");
    }
}
```

**Fix:** declare what the function returns and return it (`def note(s: str) -> bool { ... }`), or
call it as a statement and test something else. See [Functions](../../language/functions.md).

## E1174

```text
tuple index {index} is out of range for {type}
```

A tuple is indexed with a constant outside its length. `{index}` is the index written and `{type}`
the tuple's type, which states how many items it has. A negative index counts from the end, so a
two-item tuple takes `-2` to `1`.

```jac
# expect: E1174
with entry {
    pair = (1, "a");
    print(pair[2]);
}
```

**Fix:** use an index the tuple has: `pair[1]`, or `pair[-1]` for the last item. See
[Collections](../../language/collections.md).

## E1175

```text
this branch has no value, and the other branch of the conditional expression is {type}
```

One branch of a conditional expression (`a if c else b`) is a call of a function that returns
nothing, and the other has a value, so the expression cannot be given one type. The error is at the
branch with no value; `{type}` is the type of the other. Branches of two different value types are
accepted: `1 if c else "a"` has the type `int | str`.

```jac
# expect: E1175
def log(m: str) {
    print(m);
}

with entry {
    n = [log("a") if True else 2];
    print(len(n));
}
```

**Fix:** give both branches a value. Where a branch only performs an action, use an `if`
statement instead of the expression.

## E1176

```text
{type} is not a mapping
```

`**` inside a dict literal is applied to a value that is not a dict. `{type}` is its type.
`{"a": 1, **other}` copies the entries of `other` into the new dict, so `other` must have keys and
values.

```jac
# expect: E1176
with entry {
    xs = [1, 2];
    d = {"a": 1, **xs};
}
```

**Fix:** unpack a dict (`{"a": 1, **{"b": 2}}`). To put a list's items into a list, use `*` in a
list literal. See [Collections](../../language/collections.md).

## E1177

```text
an edge leads to nodes, not edges
```

An edge reference that asks for edges (`[edge -->]`) starts from an edge. From an edge, a reference
gives the node the edge leads to; there are no edges between an edge and its nodes to list.

```jac
# expect: E1177
node City {}

edge Road: City --> City {}

walker Tour {
    can cross with Road entry {
        visit [edge -->];
    }
}
```

**Fix:** drop the `edge` word to continue to the node the edge points to: `visit [-->];`. See
[Edge references](../../language/edge-references.md).

## E1178

```text
edges lead from nodes, found {type}
```

An edge reference starts from something that is not a node. `{type}` is the type of the starting
point: the expression written before the arrow, or `here` when none is written.

```jac
# expect: E1178
with entry {
    n = 5;
    print([n -->]);
}
```

**Fix:** start from a node: `[a -->]` where `a` is an instance of a `node` archetype, or `[-->]`
inside an ability that runs on a node. See [Edge references](../../language/edge-references.md).

## E1179

```text
isinstance() takes a class, a builtin type or a tuple of them
```

The second argument of `isinstance()` is not a type. It takes a class, a builtin type such as `int`
or `str`, or a tuple of those. An enum is not accepted there.

```jac
# expect: E1179
with entry {
    n = 5;
    print(isinstance(n, 5));
}
```

**Fix:** name the type: `isinstance(n, int)`, or `isinstance(n, (int, str))` for either. To
compare values, use `==`.

## E1180

```text
{type} is not hashable
```

A value of a type that cannot be hashed is used as a dict key or a set member, or passed to
`hash()`. `{type}` is the type. An `obj` is compared by its fields, and an object compared by value
has no hash unless its class defines `__hash__`; the same holds for a class that defines `__eq__`.
A `list`, a `dict` and a `set` are never hashable.

```jac
# expect: E1180
obj Point {
    has x: int = 0;
}

with entry {
    seen: dict[Point, int] = {};
    print(len(seen));
}
```

**Fix:** define `__hash__` from the fields that equality compares, or key by a value that is
hashable (an `int`, a `str`, a tuple of them):

```jac
obj Point {
    has x: int = 0;

    def __hash__ -> int {
        return hash(self.x);
    }
}

with entry {
    seen: dict[Point, int] = {};
    seen[Point(x=1)] = 5;
    print(seen[Point(x=1)]);
}
```

```output
5
```

## E1181

```text
an edge reference's destination is a node, found {type}
```

The destination written after an arrow in an edge reference is not a node. `{type}` is its type.
`[a --> b]` gives `b` if an edge leads from `a` to it, so `b` must be known to be a node; a value
typed `any` is not.

```jac
# expect: E1181
node City {}

with entry {
    a = City();
    b: any = City();
    print([a --> b]);
}
```

**Fix:** give the destination a node type (`b: City = City();`), or filter by type instead of by
a value: `[a --> [?:City]]`. See [Edge references](../../language/edge-references.md).

## E1182

```text
'{name}', which {what} names, is not wired into '{consumer}': wire it in with '{wire}'
```

A module calls another space's function, or spawns its walker, and a type in that function's
signature (or among the walker's fields) is one the calling module is not wired. `{name}` is the
type, `{what}` what names it (`count_notes()'s signature`, `walker AddNote`), `{consumer}` the
calling module and `{wire}` the wire that would give it the type, from the module that declares
it: the other space's module itself, or a module no space holds. Without that wire the caller has
no class to make the value from, so the crossing can send nothing of that type. It arises from an archwire
such as this one, when `client` calls `count_notes() -> Summary`:

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph layers {
    layer shapes { model; }
    layer service { notes; }
    layer caller { client; }
}

graph import {
    edge Calls: service --> caller;
    edge Types: shapes --> service;

    notes ++> client { count_notes }
    model ++> notes { Summary }
}
```

**Fix:** add the wire the message gives (`model ++> client { Summary }`, with the caller's layer
among the rule's targets: `edge Types: shapes --> service | caller;`), and name the type where the result is
kept (`s: Summary = count_notes();`), since a wired name must be used ([E1146](e11-1.md#e1146)). See
[Crossings](../../apps/crossings.md).

## E1183

```text
'{member}' holds fields: it is made, and a case matches it, with parentheses that give or take them
```

A member of a sum that holds fields is named without its parentheses: as a value, or as a value
pattern in a case. `{member}` is the member. A member that holds fields is no value of its own:
one is made with its fields, `Shape.Circle(1.0)`, and matched by a class pattern, `case
Shape.Circle(r):`. A member with no fields is named alone.

```jac
# expect: E1183 x2
enum Shape {
    Circle(r: float),
    Empty,
}

def round(s: Shape) -> bool {
    made = Shape.Circle;
    match s {
        case Shape.Circle:
            return True;
        case _:
            return False;
    }
}
```

**Fix:** give or take its fields: `made = Shape.Circle(1.0);`, `case Shape.Circle():`.

## E1184

```text
{name} is a sum, whose members hold fields, and it is not {what}
```

A sum is used as an enum of single members is: called with a value to find a member
(`Shape(1)`), or indexed by a member's name (`Shape["Empty"]`). `{name}` is the sum and `{what}`
what it was asked to be. A sum's members are made from their fields, so no value or name stands for
one.

```jac
# expect: E1184 x2
enum Shape {
    Circle(r: float),
    Empty,
}

with entry {
    print(Shape(1), Shape["Empty"]);
}
```

**Fix:** make the member: `Shape.Circle(1.0)`, `Shape.Empty`.

## E1185

```text
{name} is not an interface, and an impl that names it conforms {type} to it
```

An impl with a base list, `impl Meters(Plain) { ... }`, names a class that is not an interface.
`{name}` is the class and `{type}` the type the impl was to conform. An impl written apart from a
type conforms it to an interface, an `obj` of abstract methods and compile-time members; it does
not make a class a base of another.

```jac
# expect: E1185
obj Plain {
    has n: int = 0;
}

struct Meters {
    has v: float = 0.0;
}

impl Meters(Plain) {}
```

**Fix:** name an interface, or give the type what the class has some other way. See
[Interfaces](../../language/interfaces.md#conforming-apart-from-the-type).

## E1186

```text
{type} has no method '{name}' of its own, and its conformances to {ifaces} each give one: name the interface, as {iface}.{name}(x)
```

A method is called on a value whose type has no method of that name, and more than one of the
type's conformances that the calling module sees gives one. `{type}` is the type, `{name}` the
method and `{ifaces}` the interfaces whose conformances give it. Each conformance's method belongs
to it, and nothing says which one the call means.

```jac
# expect: E1186
obj Shown {
    def show -> str abst;
}

obj Told {
    def show -> str abst;
}

struct Tack {
    has n: int = 0;
}

impl Tack(Shown) {
    def show -> str {
        return "shown";
    }
}

impl Tack(Told) {
    def show -> str {
        return "told";
    }
}

with entry {
    print(Tack().show());
}
```

**Fix:** name the interface: `Shown.show(Tack())`.

## E1187

```text
the impl conforming {type} to {iface} gives {member}, which {iface} does not declare
```

An impl that conforms a type to an interface gives a method or a compile-time member the interface
does not declare. `{type}` is the type, `{iface}` the interface and `{member}` what the impl gives.
A conformance gives what its interface requires, and may give its own method in place of a
default the interface has; a method of the type's own is declared in the type.

```jac
# expect: E1187
obj Shown {
    def show -> str abst;
}

struct Pin {
    has n: int = 0;
}

impl Pin(Shown) {
    def show -> str {
        return "pin";
    }

    def spare -> int {
        return 2;
    }
}
```

**Fix:** declare the method in the type (`struct Pin { ... def spare -> int; }`), or leave it out.

## E1190

```text
a complex is immutable; '{name}' cannot be assigned
```

An assignment writes the `real` or `imag` part of a complex number. `{name}` is the part. A
`complex` is a value like an `int`: it has no parts that can change in place.

```jac
# expect: E1190
with entry {
    z = complex(1.0, 2.0);
    z.real = 3.0;
}
```

**Fix:** make a new value: `z = complex(3.0, z.imag);`. See
[Numbers](../../language/numbers.md).

## E1191

```text
cannot assign to {what} of {type}
```

An assignment writes an item or a slice of a value that cannot be changed that way. `{what}` is
`an item` or `a slice` and `{type}` the value's type. A `str`, a `tuple` and `bytes` are immutable;
a bare `ptr` has no element type to write.

```jac
# expect: E1191
with entry {
    name = "jac";
    name[0] = "J";
}
```

**Fix:** build a new value and rebind the name: `name = "J" + name[1:];`. Use a `list` (or a
`bytearray` for bytes) for data that changes in place. See [Strings](../../language/strings.md).

## E1194

```text
cannot infer {param} for {callee}
```

A call to a generic function or class does not determine one of its type parameters. `{param}` is
the parameter and `{callee}` the call. A type parameter is worked out from the arguments, so one
that appears only in the return type has nothing to be worked out from.

```jac
# expect: E1194
def empty[T] -> list[T] {
    return [];
}

with entry {
    xs = empty();
}
```

**Fix:** write the type argument at the call:

```jac
def empty[T] -> list[T] {
    return [];
}

with entry {
    xs = empty[int]();
    xs.append(1);
    print(xs);
}
```

```output
[1]
```

See [Generics](../../language/generics.md).

## E1195

```text
only a named function can be a C callback
```

A lambda or another computed value is passed where a C function expects a
function pointer, or assigned to a `Callable` field of a C record, or a lambda written in place is
given to `ptr()`. C calls the pointer with no closure, so only a function declared by name with
`def` can be one, or `None`, or the conversion of a function value to a C function pointer
(`Callable[[int], int](f)`), whose C address is the value's: a variable, a parameter or a field
holding a function converts so, and one that has no C address raises `TypeError` as the program
runs ([Callbacks](../../interop/c-libraries.md#callbacks)).

```jac
# expect: E1195
import from c {
    def qsort(base: ptr, n: int, size: int, cmp: Callable[[ptr, ptr], i32]);
}

with entry {
    qsort(ptr(0), 0, 8, lambda (a: ptr, b: ptr) -> i32 { return i32(0); });
}
```

**Fix:** declare the callback as a module-level function and pass its name:
`def same(a: ptr, b: ptr) -> i32 { return i32(0); }` and `qsort(ptr(0), 0, 8, same);`; a function
value held in a variable is passed converted, `qsort(ptr(0), 0, 8, Callable[[ptr, ptr], i32](cmp))`.
See [C libraries](../../interop/c-libraries.md).

## E1196

```text
'{name}' is already a {type} here
```

A local that already has a type is declared again with a different one. `{name}` is the local and
`{type}` the type it has. A local has one type for the whole function: the one it is declared with,
or that of its first assignment. Python lets a name hold values of different types in turn; here
it does not.

```jac
# expect: E1196
with entry {
    n = 1;
    n: str = "one";
    print(n);
}
```

**Fix:** use a second name for the second value (`label: str = "one";`), or declare the local
once with a union type (`n: int | str = 1;`). See [Variables](../../language/variables.md).

## E1197

```text
in opens a Region, not {type}
```

The statement `in r { ... }` is given a value that is not a `Region`. `{type}` is its type. `in`
as a statement opens a memory region for its body; it is not a membership test and not a loop.

```jac
# expect: E1197
with entry {
    n = 5;
    in n {
        print(n);
    }
}
```

**Fix:** open a region (`r: own Region = Region();` then `in r { ... }`), or write `for x in xs`
or `if x in xs` if a loop or a test was meant. See [Memory](../../language/memory.md).

## E1199

```text
a bare ptr has no element type; cast it to ptr[T] to view it
```

A bare `ptr` is asked for a view or a typed access (`p.view(n)`, `p.load(i, ...)`,
`p.store(i, v, ...)`, `p.vector(i, n)`). A bare `ptr` is an address with no element type, like
C's `void *`, so there is no element size to read or write by.

```jac
# expect: E1199
import from c {
    def malloc(n: int) -> ptr;
}

with entry {
    p = malloc(8);
    v = p.view(8);
}
```

**Fix:** cast the pointer to its element type first:

```jac
import from c {
    def malloc(n: int) -> ptr;
}

with entry {
    p = malloc(8);
    v = ptr[u8](p).view(8);
    v[0] = 7;
    print(v[0], len(v));
}
```

```output
7 8
```

See [C libraries](../../interop/c-libraries.md).
